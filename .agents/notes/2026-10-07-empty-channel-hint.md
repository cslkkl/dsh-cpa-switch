# 决策：空渠道的说明（2026-10-07）

状态：生效

## 问题

真机反馈：**0 个账号的渠道，面板里只有一个虚线加号座，看着像坏了。**

`.addCard` 的注释写着「虚线是它与真实账号卡唯一的区别」—— 而虚线只说明
「这是个入口」，**不说明**「这里本该有东西、现在一个都没有」。

更要紧的是**什么时候不许说**：`accountsResource.error` 非空时条数必然是 0，
先看条数就会把「读不到」判成「确实没有账号」，用户会去重加一个已经存在的号。

## 决策

**判定收进纯函数 `src/client/empty-hint.ts`，说两句：主句 + 引导句。**

判定顺序即语义，`loading` 与 `error` 都排在 `count === 0` **之前**：

| 情形             | 说什么   | 为什么                                       |
| ---------------- | -------- | -------------------------------------------- |
| 读成功、0 个账号 | 说       | 这是一个**事实**                             |
| 读成功、有账号   | 不说     | 没什么可说的                                 |
| **读失败**       | **不说** | 我们并不知道有几个账号                       |
| 加载中           | 不说     | 那段归骨架；说了会「还没有账号」与骨架卡同屏 |

呈现上三条：**独立一行**（不是卡片、也不并入 `.failed`）、在 `.grid` **之外**、
与工具栏和网格**同一条左轴**（不居中）。

引导句里的按钮名走 `{action}` 占位符取 `addAccount`，不在文案里硬编。

## 替代方案（强制）

- **并进 `.failed`**：`.failed` 的注释写明它是 **failure-only**（2026-10-07 刚从
  「还没有内容」收敛过来）——两者再共用名字，同一个位置又会在一处读作「读取中」
  另一处读作「坏了」。这正是它当初被拆开的理由。
- **画成一张假卡片**：虚线座是**入口**、这一行是**关于渠道的数据**；
  画成卡片会让它假装是上面那些座位之一，而它是唯一不可点的「卡」
- **居中**：网格列宽 260px、加号座就在左边缘，居中会与它对齐不到任何轴
- **说明块放进 `.grid`**：`grid-auto-rows: 1fr` 让所有隐式行等高 ——
  两行字会被拉到与账号卡同高（判据已钉住这条）
- **读失败时也说**：把「读不到」讲成「没有」，是本仓一直挡的那类假数据
  （同 `meter-text.ts` 的「缺数不填 0」、`status-text.ts` 的「缺一个版本号就不提数字」）

## 影响

**收益**：空渠道不再是「一个孤零零的加号」；且**读失败时不会撒谎**。

**代价**：多两行文案（中英各一对新键）；说明块的呈现位置成了一条硬约束 ——
放进网格或改成居中都会**不报错地**变难看，交给 `tests/empty-hint.test.ts`
里的两条结构守卫。

## 复验

浏览器半端改动，`pnpm build` 后**刷新页面**。复验需要一个 0 账号的渠道：
把某个单号渠道的号全删掉，或看一个还没加过号的渠道 —— 应看到
「这个渠道还没有账号」+「点下面的『+ 添加账号』，在浏览器里完成登录即可」，
且读失败时（例如停掉 CPA）这两句**不出现**。
