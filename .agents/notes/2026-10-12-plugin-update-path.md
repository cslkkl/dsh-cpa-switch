# 决策：渠道插件不给自动更新，但必须**可见、可点、可回退**（2026-10-12）

状态：生效

## 问题

`prepare()` 的跳过判据是「exe 存在 / dll 数 > 0」，而面板上「一键准备环境」走的就是它。

于是渠道插件**永远不会更新**：本机实测停在 10-04 的构建（qoder ~0.8.45），
而上游当天已是 **v0.8.66** —— 期间上游修掉了「`developer` 角色被网关拒」那个
**整轮对话 500** 的缺陷（`f496983 … normalize the developer role, fixes #34`）。

「只补缺件」本身是对的（见 F5）：静默升级会把用户正跑着的 exe 覆盖掉，
而上游随时可能改行为（模型目录、请求形状、签到协议都改过）。
坏的是**只有这一半** —— 代码注释写着「需要用户显式点重装」，
而那个入口从来不存在（`removeDir` 导出后零调用者）。

## 决策

三条一起给，缺一条都不成立：

1. **记下装的是哪个 tag**：新状态文件 `storages/cpa-panel-install.json`。
   判据是**上游 release 的 tag 相等**，不解析版本号。
2. **面板上报出来**：`GET /api/v1/cpa/plugins-update` + 状态条下面一行。
3. **用户点了才换**：`POST` 同路径 —— 先停 CPA，再**覆盖替换**，失败自动还原。

拆分与落点：

- 「把一个来源装到磁盘上」从 `prepare()` 里抽成 `setup/install.ts` 的 `installSource`，
  「要不要跳过」变成它的 `force` 参数 —— 否则「强制更新」只能在外面重写一遍
  下载 / 校验 / 解压（第一件被漏掉的通常就是 sha256 校验）；
- 「停 CPA」是进程语义，落在 `CpaRuntime.stop()` 的第三个名字上；
- 「停 → 换 → 报告」这条序列落在新域 `ops/plugin-update.ts`：
  它同时看得见 `runtime` 与 `setup`，而 `setup/` 层**不许**依赖 `runtime`。

## 替代方案（强制）

- **每次自动更新**：上游随时改行为，静默升级等于把上游的风险直接灌给用户；
  与本仓「不越权」的既有口径相反。**否决**。
- **靠比对 asset 的 sha256 判有没有新版**：`asset.digest` 在旧 release 上可能为空
  ⇒ 静默退化成「无法比较」；上游重打包但不 bump 版本时会误报「有新版」；
  且 sha256 对用户不可读。**不采用**（tag 相等零解析、零边界）。
- **解析 semver 比大小**：只是为了让文案能说「新版」，而要写一套解析 + 一个纯判据文件
  - 前导 `v` / 后缀等边界。改成**两个 tag 都显示**，谁新谁旧由人看 —— 同一个目的，零解析。
- **拿 `usage-queue` 当「真值」源**（顺带解决「上游实际跑了哪个模型」那类观测）：
  它**是破坏性读取**（pop），retention 60 秒、还要 `usage-statistics-enabled`，
  会与别的消费者抢记录。**不做**；真要那类观测得让上游加非破坏性接口。
- **把渠道插件源码接管进本仓**（MIT，本机有 Go 工具链）：非测试代码 5.8 万行、
  5 条渠道、跨工具链，会破坏本仓的分层检查与 CI 面。要自己定义就照
  `SOURCES.cpa` 的既有模式换 `SOURCES.plugins.repo` 指向自己的 fork ——
  **插入点是一个常量**，本仓架构零改动。
- **自动重启 CPA**：替用户决定了「重启」。改成更新完**不自动起**，
  把 `stopped` 如实回给界面，用户自己点「启动」。

## 影响

- 收益：卡住拿不到上游修复这件事有了出口；看见版本差、一键换、失败可还原。
- 代价：多一个状态文件、多一个路由、多一个业务域；
  「有没有新版」的判据依赖上游**老实 bump tag**（重打包同 tag 时本记录会说「已是最新」——
  这条边界写在 `state.ts` 的 `installRecordPath()` 上方，不假装它更准）。
- 没解决的：`model-caps.ts` 那类「上游没填值」的问题与本文无关；
  「上游到底实际跑了哪个模型」也不由它解决 —— qoder 网关一律自称 `auto`，
  那句告警区分不了，见[依据记录](2026-10-12-qoder-reports-auto-in-response.md)。
