# 决策：卡片纵向几何收成一处、状态改属性（2026-10-07）

状态：生效

## 问题

卡片的「高度」这个事实原先散在**四处**，而且**四份都写错了同一个数**：

| 处                            | 内容                                                                                     |
| ----------------------------- | ---------------------------------------------------------------------------------------- |
| `panel.module.css` 的 `.card` | `height: 222px` + 注释里重算一遍                                                         |
| 同文件的槽位表注释            | `head 21 / tag 19 / numbers 36 / meter 18 / facts 36 / actions 28 = 158 + 40 + 24 = 222` |
| `src/client/README.md`        | 同一张表 + 同一道算式 + 「改任何槽位高度都要重算这个数」                                 |
| `tests/card-slots.test.ts`    | 自己重抄一份 `[21,19,36,18,36,28]`，算出来还是 222                                       |

**为什么四份都错**：`height` 在 content-box 下是**内容**高度，而那道算式把上下内边距算进去了。
所以「222px 的卡片」实测一直是 **248px**（+24 内边距 +2 边框）。六个槽位加五个间距
本来正好 `198 = 222 − 24` —— 说明当初是**按 border-box 想**的，而这个仓没有全局 `box-sizing` 重置。
多出来的 24px 变成了 `justify-content: space-between` 摊掉的行距，所以从外观上看不出来。

**第二处错**（真机量出来的）：`numbers` 槽位声明 36px，而它装的是「标签 + 数字」两行 ——
实测 `.label` 12px/18px 与 `.value` 16px/24px = **42px**。内容一直溢出 6px，
被 `.card` 的 8px 间距吃掉，谁也没看见。声明的高度不等于真实内容高度时，
「六槽位之和 = 卡片高度」这个算式算的是假的。

**第三处**：`cardHead` 的 21px **在 CSS 里根本没声明**，它是昵称那行文字的自然高度
（14px × 1.5），却被算进了「六槽位之和」。

## 决策

**槽位高度定义成 `.card` 上的 `--cpa-slot-*`；`.card` 的高度是它们的 `calc()`；算式只描述内容高度。**

- `.card` 是**唯一来源**：六个槽位高度、间距、内边距都只在这里声明一次。
- 六个槽位规则只引用变量（`height: var(--cpa-slot-tag)`），**不许再写死 px**。
- `.card` 的高度算式 = 六槽位之和 + 五间距，**不含内边距、不含边框** ——
  它们在 content-box 之外；把内边距算进来正是那个错。
- `--cpa-slot-numbers: 42px`（等于它真实装的两行），`--cpa-slot-head: 21px` 显式声明。
- 判据 `tests/card-geometry.test.ts` **不再抄任何数字**：它从 CSS 里读出那六个变量、
  把 `calc()` 求值、验证「卡片内容高度就是六个槽位之和」。于是「改槽位要重算高度」
  这件事**由算式自己保证**，没有第二处要跟着改。
- 同时钉住两条会静默改含义的写法：算式里不许出现内边距/边框、`.card` 不许改成 `border-box`。

**状态改用 `data-*` 属性**：`data-selected` / `data-disabled`（条件写 `|| undefined`）。
类名拼接把「当前是什么状态」变成 TS 里的字符串运算，而那是样式的事；
`data-*` 之后 TS 只声明**条件**，长什么样由 CSS 决定。宿主自己的写法也是 `data-x={cond || undefined}`。

**说明行收成一行**（`--cpa-slot-facts: 18px` + `-webkit-line-clamp: 1`）：这一行常态就是一行
（`factsOf()` 最多拼三项，每项只在真有值时出现），36px 是给认不出的上游档位名留的容量。
⚠️ 夹断必须与高度同步收到 1 —— 高度一行而夹断两行时，第二行会被**从字形中间切开**，
而不是以省略号收尾。完整值仍在 `title` 属性里。

## 替代方案

- **把 `.card` 改成 `box-sizing: border-box`**：这样原来那道（把内边距算进来的）算式反而对了。
  否决原因：那要赌边框的亚像素取整 —— 声明的 `0.5px` 边框实测按 `1px` 参与布局，
  算式里写 `2 × 0.5px` 会与真实盒子差 1px。改成 border-box 还让「同一份算式得到另一种盒子高度」，
  而那不报错。
- **保留四处各写一份、只把数字改对**：改一次要对四处，且判据仍在拿自己抄的那份算 ——
  「改槽位忘了改卡片高度」照样是绿的。本次要消灭的正是这个。
- **`numbers` 保持 36px、把里面两行的行高压小去凑**：那会改文字的观感，而 36px 本来就只是写错了。
- **给说明行做「按内容自适应高度」**：卡片就不等高了，四渠道切页签时行位置会漂 —— 与定高槽位的整个设计冲突。
- **状态继续拼类名**：能工作，但两个来源（类名 + 属性）并存时必然会分家；
  而且 DevTools 里看不出「这张卡当前是什么状态」。

## 影响

- **可见变化**：卡片盒子 **248px → 212px**（矮 36px）。其中 24px 是纠正「内边距被算了两遍」，
  6px 来自 `numbers` 声明从 36 改成真实的 42（同时消除了那处 6px 溢出），
  18px 来自说明行两行收成一行。
- 六个槽位现在**正好**填满内容高度，`justify-content: space-between` 不再有松动的 24px 可摊。
- 网格行高、添加卡高度跟着变（`grid-auto-rows: 1fr`）。
- 骨架（见另一条决策记录：首屏骨架与扫光）复用 `.card` 与六个槽位类，
  所以它**自动跟着变**，不需要单独改。
- 真机复验：内容高度 == 槽位之和、盒子 == 内容 + 内边距 + 边框、无槽位溢出、四渠道等高、
  添加卡同高、状态在属性上。
