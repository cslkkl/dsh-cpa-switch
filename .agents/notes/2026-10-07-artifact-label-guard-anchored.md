# 决策：产物判据「Switch 未被包在 label 里」改锚真实写法并内建自证（2026-10-07）

状态：生效

## 问题

`scripts/verify-artifacts.cjs` 有一条 F31 的判据：`Switch` 不许被包在 `<label>` 里。

它的实现一直是 `!/label[^>]*\{[^}]*Switch/.test(clientCode)` —— 一个裸子串匹配。

那条注释自己就记着这个坑（2026-10-05 实踩：`--dsw-alias-label-primary` 与 `headSwitch` 被连成一段而误判），并给出了「先剥掉内联 CSS」的对策。

**2026-10-07 它又红了一次，而且是同一个原因**：剥掉 CSS 之后，类名映射表里仍有 `headSwitch` 这个**字符串**，而骨架屏新增的 `data-shape="summary-label"` 里含子串 `label` —— 两者被正则跨着 736 字节连起来，判据把正确的代码判成红。

两次都说明：**对策（剥 CSS）治的是来源，没治匹配面**。裸子串匹配在任何新代码面前都可能再被连起来。

## 决策

判据改为锚在**产物里的真实写法**上，并**内建自证**：

- `label` 只认真实 JSX 标签：`jsx)("label",`（注意 `jsx` 与 `"label"` 之间隔着 `)(` —— 写成 `jsx("label"` 一个都匹配不到，这条是被自证抓出来的）。
- `Switch` 只认 primitives 的组件引用：`_deepseek_ai_dsh_client_ui_primitives.Switch`。产物里 `Switch` 共出现 7 次，其中 4 次是 CSS 类名 `headSwitch`、1 次是注释，**只有 2 次是真引用** —— 所以「label 之后 400 字节内出现 `Switch`」这种窗口判定必须锚在引用上。
- 三条自证随脚本一起跑：真缺陷要抓到、只有类名时不许命中、`div` 包 `Switch` 的正确形状不许命中。

## 替代方案

- **只把窗口从 400 字节调小**：治标。误配的长度取决于中间隔了多少代码，没有一个「安全」的值。
- **继续用裸子串、只在红的时候人工判断**：这正是它连红两次的原因 —— 一条总是误报的判据最后会被无视，而它保护的缺陷（label 转发点击）是真事。
- **删掉这条判据**：丢掉 F31。真缺陷要真机点击才看得见（`Switch` 渲染 `<button onClick>`，label 会再转发一次），正是需要产物级判据的地方。
- **改成渲染断言**（真渲染一棵树查父子关系）：本仓 Node 侧没有 DOM 环境（`environment: 'node'`），要引入 jsdom 与一套渲染依赖 —— 为一个判据换掉测试环境不划算。

## 影响

- 判据从「可能误报」变成「误报即自证失败」，而自证是这个脚本的一部分、每次构建都跑。
- 产品数从 32 变成 35（三条自证）。
- 代价：判据耦合了产物里 `jsx` 调用与 primitives 的外部引用形态。形态变了会红 —— **但那是应当有人看一眼的变化**，不是静默放过。
