# 决策：面板里勾选「哪些模型出现在 DSH 的模型选择器」（2026-10-13）

状态：生效

## 问题

DSH 对话界面的**模型选择器**里挤着本插件推上去的全部模型（本机实测 96 行）。
用户只用其中几个，但每次选模型都要在那个长列表里翻。

维护者的诉求（原话）：

> 每个渠道里的那么多模型进行分组，比如 workbuddy 的分一组、trae 的分一组，
> 然后再把 workbuddy 渠道里面的那么多模型进行筛选，然后可以勾选隐藏。
>
> 只在对话框旁边的选择器里不显示，**但是在插件面板里还是要有**，
> 我勾选的才出现，不勾选的不出现。

## 决策

**面板里按渠道列出该渠道的全部模型，勾 = 出现在选择器；不勾的模型不进清单。**
分组不用另外做：面板本来就是**一个渠道一个页签**，所以「WorkBuddy 一组、Trae 一组」
是现成的结构。

### 一、存的是「隐藏的」，不是「勾选的」

状态文件里存**被隐藏**的那批（`cpa-panel-hidden-models.json`），空文件 = 什么都不藏。
两条默认因此都安全：

- 刚装好 / 文件丢了 ⇒ 选择器里**不会变空**（存「勾选的」时那是最可能的翻车）；
- **新模型默认出现**，不会因为「表里没有它」而静默消失。

### 二、键是（渠道, 裸名），不是行 id

行 id 会带渠道别名（`wb/glm-5.3`），而别名随上游供给面变化 ——
拿行 id 当键，上游一变就匹配不上，表现为「用户藏过的模型某天又自己冒出来」，
**且没有任何报错**。这条与目录护栏的键口径一致。

两侧共用**一份**规范化实现（`model-alias.ts` 的 `bareModelNameOf`）：
宿主写盘前归一、路由侧按 `row.bare` 判；`/models` 直接带 `bare` 给界面 ——
**浏览器半边不许引宿主模块**，让界面自己算一遍就是两处口径漂开。

### 三、「全藏」是一个独立状态，不是读失败

用户把模型全藏了 ⇒ 重试一百次也还是全藏。当成「目录读残」的后果有两层：
护栏会拦、重读链会排（面板一直刷新），而且**回推上一份**——用户勾了全藏却照旧有模型。

所以给一个可辨认的类型（`HiddenAllModelsError` → `reason: 'all-models-hidden'`），
调用方**推一份空清单**（撤下我们那几个 provider）、正常收场、不排重读链。

### 四、写入后**立刻重推**

不重推的话要等下一次目录变化才生效，而目录可能几小时都不变 ——
用户看到的是「勾了没反应」，与「勾选没保存」长得一模一样。
重推失败**只记日志、不让保存失败**：用户的意图已经落盘了。

### 五、面板照旧显示全部模型

这正是用户明确要的：**勾选的地方在面板、生效的地方在选择器**。
如果面板只显示已勾的，用户就没法把取消掉的再勾回来。

## 替代方案（为什么没这么做）

- **改 DSH 的模型选择器（宿主插件）** —— 否。那是宿主的地盘，跨插件改别人的 UI
  不受支持、且宿主一升级就崩。我们能控的是**推上去的清单**。
- **按渠道整体开关（藏一个渠道的全部模型）** —— 否。用户要的是**逐模型**，
  而渠道级粒度太粗（一个渠道里常用的往往只有两三个）。
- **把隐藏项做成插件配置字段**（像 `reasoningEfforts` 那样） —— 否。
  那是「产品设置」，而这是**界面偏好**；且配置字段写入要宿主 API，
  状态文件这条路更直接（与账号意图同规）。
- **存「勾选的」**（空文件 = 全不显示） —— 否。那是**危险默认**：
  文件丢失或首次安装时选择器会空掉，用户一个模型都选不了。
- **面板只显示已勾的模型** —— 否。用户就没法把取消掉的勾回来。
- **不重推、等下次目录变化** —— 否。用户会以为功能坏了。

## 影响

- 新状态文件 `~/.dsh/storages/cpa-panel-hidden-models.json`（与账号意图同规：
  读改写、只认 `source: 'panel'`、坏格子只丢那一格）；
- 新路由 `GET/POST /api/v1/cpa/model-visibility`；
- `route-registry` 新增 `isHiddenModel` 与 `onDisplayChanged` 两个依赖，
  以及 `HiddenAllModelsError` 这一类错误；
- `/api/v1/cpa/models` 的每一行**新增 `bare` 字段**（形状变化，两半同步改）；
- 面板新增「模型」一节（默认折叠，`<details>`）。

判据：`tests/hidden-models-state.test.ts`（落盘纪律）、
`tests/ops-model-visibility.test.ts`（域校验 + 裸名归一 + 重推通知）、
`tests/model-visibility-client.test.ts`（界面判定：方向与键）、
`tests/route-registry.test.ts` 的「隐藏模型」一组（推送过滤 + 键口径 + 全藏）。

⚠️ **未真机验证**：拉取最新 + 重启 DSH 后要看的是「取消勾选 → 保存 →
对话界面的模型下拉里那个模型消失；面板里它照旧在」。
