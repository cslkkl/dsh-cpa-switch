# 决策：面板里勾选「哪些模型出现在 DSH 的模型选择器」（2026-10-13）

状态：生效

## 问题

DSH 对话界面的**模型选择器**里挤着本插件推上去的全部模型（本机实测 96 行）。
用户只用其中几个，但每次选模型都要在那个长列表里翻。

维护者的诉求（原话）：

> 每个渠道里的那么多模型进行分组，比如 workbuddy 的分一组、trae 的分一组，
> 然后再把 workbuddy 渠道里面的那么多模型进行筛选，然后可以勾选隐藏。
>
> 只在对话框旁边的选择器里不显示，**但是在插件面板里还是要有**，
> 我勾选的才出现，不勾选的不出现。

## 决策

**面板里按渠道列出该渠道的全部模型，勾 = 出现在选择器；不勾的模型不进清单。**
分组不用另外做：面板本来就是**一个渠道一个页签**，所以「WorkBuddy 一组、Trae 一组」
是现成的结构。

### 一、存的是「隐藏的」，不是「勾选的」

状态文件里存**被隐藏**的那批（`cpa-panel-hidden-models.json`），空文件 = 什么都不藏。
两条默认因此都安全：

- 刚装好 / 文件丢了 ⇒ 选择器里**不会变空**（存「勾选的」时那是最可能的翻车）；
- **新模型默认出现**，不会因为「表里没有它」而静默消失。

### 二、键是（渠道, 裸名），不是行 id

行 id 会带渠道别名（`wb/glm-5.3`），而别名随上游供给面变化 ——
拿行 id 当键，上游一变就匹配不上，表现为「用户藏过的模型某天又自己冒出来」，
**且没有任何报错**。这条与目录护栏的键口径一致。

两侧共用**一份**规范化实现（`model-alias.ts` 的 `bareModelNameOf`）：
宿主写盘前归一、路由侧按 `row.bare` 判；`/models` 直接带 `bare` 给界面 ——
**浏览器半边不许引宿主模块**，让界面自己算一遍就是两处口径漂开。

### 三、「全藏」是一个独立状态，不是读失败

用户把模型全藏了 ⇒ 重试一百次也还是全藏。当成「目录读残」的后果有两层：
护栏会拦、重读链会排（面板一直刷新），而且**回推上一份**——用户勾了全藏却照旧有模型。

所以给一个可辨认的类型（`HiddenAllModelsError` → `reason: 'all-models-hidden'`），
调用方**推一份空清单**（撤下我们那几个 provider）、正常收场、不排重读链。

### 四、写入后**立刻重推**

不重推的话要等下一次目录变化才生效，而目录可能几小时都不变 ——
用户看到的是「勾了没反应」，与「勾选没保存」长得一模一样。
重推失败**只记日志、不让保存失败**：用户的意图已经落盘了。

### 五、面板照旧显示全部模型

这正是用户明确要的：**勾选的地方在面板、生效的地方在选择器**。
如果面板只显示已勾的，用户就没法把取消掉的再勾回来。

## 替代方案（为什么没这么做）

- **改 DSH 的模型选择器（宿主插件）** —— 否。那是宿主的地盘，跨插件改别人的 UI
  不受支持、且宿主一升级就崩。我们能控的是**推上去的清单**。
- **按渠道整体开关（藏一个渠道的全部模型）** —— 否。用户要的是**逐模型**，
  而渠道级粒度太粗（一个渠道里常用的往往只有两三个）。
- **把隐藏项做成插件配置字段**（像 `reasoningEfforts` 那样） —— 否。
  那是「产品设置」，而这是**界面偏好**；且配置字段写入要宿主 API，
  状态文件这条路更直接（与账号意图同规）。
- **存「勾选的」**（空文件 = 全不显示） —— 否。那是**危险默认**：
  文件丢失或首次安装时选择器会空掉，用户一个模型都选不了。
- **面板只显示已勾的模型** —— 否。用户就没法把取消掉的勾回来。
- **不重推、等下次目录变化** —— 否。用户会以为功能坏了。

## 影响

- 新状态文件 `~/.dsh/storages/cpa-panel-hidden-models.json`（与账号意图同规：
  读改写、只认 `source: 'panel'`、坏格子只丢那一格）；
- 新路由 `GET/POST /api/v1/cpa/model-visibility`；
- `route-registry` 新增 `isHiddenModel` 与 `onDisplayChanged` 两个依赖，
  以及 `HiddenAllModelsError` 这一类错误；
- `/api/v1/cpa/models` 的每一行**新增 `bare` 字段**（形状变化，两半同步改）；
- 面板**工具栏**上新增「模型」按钮（点开是勾选弹窗）—— 落在这一排而不是网格下面，
  是维护者真机指定的位置（第一版做成网格下面的折叠节，他**找不到**）。

判据：`tests/hidden-models-state.test.ts`（落盘纪律）、
`tests/ops-model-visibility.test.ts`（域校验 + 裸名归一 + 重推通知）、
`tests/model-visibility-client.test.ts`（界面判定：方向、键，以及下面那次事故的回归）、
`tests/route-registry.test.ts` 的「隐藏模型」一组（推送过滤 + 键口径 + 全藏）。

## 事故与教训：第一版**整个功能不存在**，而所有请求都是 200

第一版上线后维护者的反馈是「**我怎么没看见可以勾选模型啊**」。根因两层，**都不报错**：

1. **取错字段**：传输层把响应体**摊平**在结果对象上（`{ok: true, groups: [...]}`），
   而 `ApiResult` 带索引签名（`[key: string]: unknown`）—— 于是
   `useResource({ select: (result) => result.data })` **能编译通过、却永远是
   `undefined`**。清单恒为空。
2. **我自己把它藏了**：视图里写着「读失败或读到 0 个就 `return null`」。
   于是一个纯粹的接线错误，在界面上长得和「这个功能没做」**一模一样**。

两条改成纪律（已写进根 AGENTS.md 的活跃坑）：

- **`select` 取整个 `result`**，字段在**适配器**里按线上形状取（`modelsResultOf`）；
- **入口永远立着**：读不到 / 空都在界面里说清楚，**不许 `return null`** ——
  否则任何接线错误都会长成「这个功能不存在」。

判据是 `tests/model-visibility-client.test.ts` 的「真机事故回归」：拿**真实抓下来的
响应体**当夹具，外加两条源码断言（钩子里不许出现 `result.data`、视图里不许
`return null`）。源码断言确实比渲染断言脆，但这个仓库已经有过同样的取舍
（`tests/card-slots.test.ts`）—— 它守的是「有人手滑写回老写法」这类结构性回归，
**失效方式是报错而不是静默走样**。

## 事故二：勾选保存成功，但**一个都没生效**（目录护栏把它当成「读残」拦了）

第一次真机复验时，维护者勾掉了 workbuddy 的 **31 个**模型、只留一个：面板说保存成功、
状态文件也**确实写对了**，但模型选择器里**一个都没少**。日志给出了原话：

> 目录护栏拦下这一轮：比上一份少 31 行 → 不写盘、继续用上一份

**根因**：目录护栏问的是「这一轮**比上一份差**吗」（CPA 的目录只会因加号增长），
而「用户藏掉的行」在它眼里**长得和读残一模一样** —— 于是整个用户选择被原样拦回。
更糟的是**保存是成功的**（状态文件写进去了），所以现象看起来是「功能坏了」而不是
「被拦了」，用户完全没有线索。

**为什么我做过这个功能却漏了它**：我在动手**之前**就查到并写下了这条交互
（「隐藏 = 清单变短 = 会被护栏挡回去」），但实现时只把过滤放在了护栏**之前**
（对「目录读残」那一类是这样没错），**忘了护栏本身还要按（渠道, 裸名）逐行豁免**。
教训：**写下一条交互不等于处理了它** —— 判据要落在**那条交互**上，
而不是落在「我实现的那部分」上。

**修法**：给 `shrunkRows` 加一个 `isHidden(channel, bare)` 参数，**藏掉的行不参与比较**。
粒度是**藏掉的那些行**（裸名从行 id 剥前缀得到，与 `guardKeyOf` 同口径 ——
用行 id 直接比会漏掉带别名的那一半），**不是**「有隐藏就整体放行」：
后者会把护栏要治的病（读残被当成事实写盘）放回来。

**判据两条**（`tests/route-registry.test.ts` 的「隐藏模型」一组）：
一条分**两轮**验「藏了真的生效」（先建基线再隐藏 —— 只有一轮的话护栏不参与，用例假绿），
一条反例验「**没被藏**的行少了照样拦」。

## 事故三：勾选清单与选择器**不是同一批模型**（「trae 我只勾选了几个，为什么还有那么多」）

护栏修好之后，勾选**确实生效了**（清单真的重推了），但维护者发现 trae 里
「只勾了几个、还有那么多」。查下来是**两件事叠在一起**，都不报错：

### 1. 勾选清单取错了来源

面板原先从**渠道插件的模型目录**（`/models`）列清单，而**推给宿主的是路由侧的行**。
trae 实测：目录报 **20 个裸名**（`glm-5.2`、`kimi-k2.6`…），推送的行却叫
`trae/glm-5.2`、`Trae/trae/glm-5.2` —— **一个都对不上**。于是维护者勾了 18 个，
选择器里那 9 行**一个都没少**（保存成功、清单也重推了，只是没有一个键命中）。

**修法**：勾选清单必须来自**推送侧同一份数据、同一个键** —— 新增
`RouteRefresher.candidatesOf(channel)`（候选行 = **过滤之前**的那批，
所以勾掉的行还在清单里，用户能勾回来），面板改读 `/api/v1/cpa/model-rows`。

> **教训（比上一条更一般）**：「同一个概念」在两个地方各算一遍，就一定会有
> 两边对不上的一天。凡是「用户点 A、系统按 B 生效」的链路，**A 的取值来源
> 必须就是 B 的那一份**，不能是「看起来差不多」的另一份。

### 2. 裸名的前缀只剥了一层

CPA 目录里同一个 trae 模型有**三种 id 形态**：

| 目录里的 id                                       | 只剥一层       | 用户勾的     |
| ------------------------------------------------- | -------------- | ------------ |
| `glm-5.2`                                         | `glm-5.2`      | `glm-5.2` ✅ |
| `trae/glm-5.2`（**我们**写的别名）                | `glm-5.2`      | `glm-5.2` ✅ |
| `Trae/trae/glm-5.2`（上游又套了一层它自己的前缀） | `trae/glm-5.2` | `glm-5.2` ❌ |

第三条因此**藏不掉**，还在选择器里占三个条目（同一个模型三条行）。
真机数据：27 条 trae 相关 id 剥完收敛成 **16 个**模型名。

**修法**：`stripChannelPrefixes` **反复剥**（剥的条件仍是「前缀能反查成托管渠道」，
第三方 `vendor/xxx` 照旧不动）；同一（渠道, 裸名）**只留一行**，
保留**我们自己的别名形态**（写进 CPA 配置的那份，最稳定）。
目录护栏的键也走同一个实现 —— 口径漂开就会出现「隐藏被当成缩水拦回」。

> 顺带销掉了根 AGENTS.md 待办「渠道插件把同一个模型报成两条」里**我们能做的那半**：
> 上游怎么报是它的事，但**我们推上去的清单**从此一个模型一行。

## 事故四：勾选弹窗里每一行都叫「WorkBuddy」（2026-10-14）

维护者截图：弹窗里三四十行**全是「WorkBuddy」**，看不出哪个是哪个模型。

根因是**同一份「展示名」在两处各算了一遍，其中一处漏了模型名**：
选择器里那一行叫 `WorkBuddy · glm-5.3`（`toModel` 里的 `` `${row.label} · ${row.bare}` ``），
而候选行交出去的 `label` 直接就是 `row.label` —— 那是**渠道名**（`channelLabel(channel)`）。
候选行的 `label` 本来是给**别的用途**用的（组装推送行的 `name`），被顺手当成展示名交出去了。

**为什么是「变成这样了」**：这个字段在面板改读候选行（`06b2431`）那一刻才第一次
被画出来 —— 在那之前面板读的是 `/models`，展示的是上游给的 `name`；
换成候选行之后，`label` 是渠道名这件事才第一次暴露到界面上。
而当时的真机验收只验了「取消勾选后那一行真的没了」（`32 → 31`），
**没验「每一行分别显示什么」**——于是它带着这道疤过了一个版本。

真机实证（修复前，从浏览器直接打 `/api/v1/cpa/model-rows`）：
workbuddy **31 行 `distinctLabels` 只有 `WorkBuddy` 一个值**，trae 20 行同理只有 `Trae`。

**修法**：抽出 `displayNameOf(row)`，`toModel` 的 `name` 与候选行的 `label` **都从它取** ——
一份实现、两处引用，漂开就没有第二次机会。判据加了「候选行展示名 = 推送行 name」
且「同渠道内展示名互不相同」（全是同一个词正是这次的形态）。
已用变异验证：把 `label` 改回 `row.label` 后新判据**当场变红**
（`expected 'Qoder' to be 'Qoder · dfmodel'`），而其余 84 条全绿 —— 说明它真的咬住了这次的事故。

> **教训（与事故三同源，但方向相反）**：事故三是「用户点 A、系统按 B 生效」——
> A 的来源必须就是 B 的那一份。这一条是**反过来**：B 的**展示**也必须来自同源 ——
> 凡是「同一个概念要显示给人看」，就不要在第二处**重新拼一遍**，
> 哪怕那一处此刻「看起来正好是这个名字」。
>
> ⚠️ 这次的形态尤其阴：`label` 这个字段名在两侧都说得通
> （渠道名也是一种 label），所以**类型检查、测试、请求状态**全是绿的，
> 只有真机截图才看得出「全是同一个词」。判据因此必须落在
> 「**两处字符串相等**」与「**行内互不相同**」上，而不是「label 非空」。

## 真机验证（2026-10-13）

- ✅ 按钮出现在工具栏、弹窗列出 32 个 workbuddy 模型；
- ✅ 取消勾选 `glm-4.6` 保存后**推给宿主的清单里那一行真的没了**（32 → 31），
  同渠道其它模型与其它三个渠道一个没少（验后已还原）；
- ✅ 用**真实数据**跑修复后的护栏：维护者那份勾选（workbuddy 藏 31 / trae 17 /
  qoder 12 / zcode 9）算出来 **97 → 15 行，被拦下 0 行**；
- ✅ 用**真实目录**（106 条 id）验反复剥前缀：trae 相关 27 条 → **16 个模型名**；
- ⚠️ **待维护者重启 DSH 后确认**：勾选清单里每个模型**只出现一次**，
  且勾掉之后选择器里真的没有它（宿主半端要重启才加载新产物）。

## 已知的小瑕疵（记录，暂不修）

启动时的**快路径**会把磁盘缓存里那份清单**原样**推一遍（它不套隐藏过滤，
理由见「启动不等读」那条不变量）—— 所以重启后**可能短暂**看到被隐藏的模型，
随后被慢路径推的正确清单替换。要消掉它得让快路径也过一遍过滤，
而那一步动的是「重载空窗」那条最敏感的链，收益只是消除一次闪烁，暂不动。
