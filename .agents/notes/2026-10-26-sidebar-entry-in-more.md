# 决策：侧栏入口收在「更多」菜单里，不给位置选择（2026-10-26）

状态：生效

## 问题

侧栏顶部那列插件图标越来越挤。宿主 `0.2.1-rc.3` 给了官方解法：面板列表末尾一个
「更多」按钮，把低频入口折进去。维护者要本插件也这么做 —— **打开「侧栏入口」开关
后，入口出现在「更多」里**，而不是删掉那个开关。

## 决策

打开开关 ⇒ 只注册 `sidebar.panellist.actions`（侧栏「更多」菜单里一行），
**不注册** `sidebar.panellist`（栏上那一行）。菜单里那一行自己画，点了进面板
（`layout.selectPanel(PANEL_ID)`）。

**不给「钉在栏上」这一档**（第一版做过，维护者否掉）：这一行偏好只该回答一个问题
—— 要不要入口；「放哪」由我们定。栏上是宿主与所有插件共用的一列，默认不占。

## 替代方案（强制）

- **调宿主 `onPinnedChange(PANEL_ID, false)` 把自己收起来**：宿主的 pin 机制本身
  就是给这个用的，但那个回调只发给 `sidebar.panellist.actions` 的注册者，而注册者
  的组件**只在「更多」被点开时才挂载**（宿主 `Menu` 的实现是 `const list = open && …`）
  —— 靠它收纳等于「用户第一次点开菜单才收纳」。且那个状态是**内存态**
  （`createPanelPins` 注释原话：held in memory until plugin reload），刷新即忘。
- **位置二选一（收在更多 / 钉在栏上）**：第一版实装过，维护者定案删掉 ——
  多一行偏好、多一个字段、多一条互斥判据，换来的只是一个「不希望有人默认占栏上」
  的默认值。
- **两档都注册**（栏上留图标 + 菜单里也放一行）：同一个面板两个入口，而「更多」
  的意义正是减少重复。

## 影响

- 偏好文件**没有**新增字段：仍然只有 `sidebarEntry`。老的 `{sidebarEntry: true}`
  文件照读，行为从「栏上一行」变成「更多里一行」—— 这是这次改动的**本意**。
- 面板底部那一行开关照旧，只有提示文案改了：说明开启后从「更多」进。
- **旧宿主兜底**：「更多」那个座是 `0.2.1-rc.3` 才声明的，而 `slots.inject` 对
  **从未声明**的槽位**永远不跑回调** ⇒ 默认档在旧宿主上会变成「侧栏里什么都没有，
  而开关明明是开的」。所以等 2 秒仍未见声明就退回栏上那一行；槽位后来声明时自动
  摘掉兜底（保持只有一个入口）。代价：旧宿主上看到的是栏上那一行 —— 但那是
  **看得见**的降级，不是静默消失。
- 菜单里那一行**必须带 16px 图标**（用我们自己的 `PanelGlyph`）：官方那两行都有
  图标，不给的话文字贴到最左边，一眼看出不是亲生的。
- 判据：`tests/ops-prefs.test.ts`（默认关 / 脏值关 / 文件为开时照文件）、
  `tests/sidebar-visibility.test.ts`（未读到 ⇒ 不可见 / 值没变不通知）、
  `scripts/verify-artifacts.cjs`（注册在「更多」座而不是栏上座、行有 id/order/图标、
  开关为关时摘除、disposer 被接住、旧宿主兜底存在）。
