# 决策：按三重复测给档位分类，摘掉假旋钮、对调反向的（2026-10-12）

状态：生效

## 问题

模型的「思考档位」（界面上的 **关 / 开**）在多数模型上是**假旋钮**，而且比想象的普遍：

- **关不掉**：选「关」模型照样思考 —— 你按不动这个按钮；
- **方向相反**：选「开」反而比「关」**想得更少** —— 给的方向是错的；
- **真·假 high**：两档都完全不思考 —— 开关完全没有意义。

维护者的两条口径（本次拍板）：

1. **关不掉的删掉档位**（不留一个假的「关」）；
2. **方向相反的对调 `off` / `high`**，让界面语义回到「关 = 想得少、开 = 想得多」。

## 为什么先重测（这一步是关键）

上一版分类建立在**单次**测量上，而本次三重复测**推翻了它的一半**：

| 模型         | 单次（旧）           | 三次（新）                                                   |
| ------------ | -------------------- | ------------------------------------------------------------ |
| `wb/glm-5.3` | 方向相反（585 / 38） | off=[62,12,4] high=[60,12,60] —— 两档都在 **0 附近抖**       |
| `gmodel`     | 方向相反（309 / 48） | off=[216,142,413] high=[67,51,38] —— 仍反，但量级不同        |
| `kimi-k3`    | 方向相反             | off=[769,217,232] high=[135,524,192] —— **区间重叠，测不准** |
| `wb/glm-5.1` | 真开关               | off=[1100,1436,1599] high=[1092,1662,914] —— **测不准**      |

所以定了一条**保守判据**：**两档的区间只要重叠，就判「测不准」，一律不动**。
理由：「测不准」与「真没差别」是两回事 —— 前者可能其实是真开关，删了就丢掉一个有用功能。

（另：上一版数据本身也来自**旧凭据 / 旧区域**，报告自己标了这条边界。）

## 决策

**四类，逐模型标在校准表上**（判据 `tests/model-caps.test.ts`）：

| 类         | 判据                       | 动作                                    |
| ---------- | -------------------------- | --------------------------------------- |
| 真开关     | 关 = 0 字、开 ≥ 100 字     | **不动**                                |
| 真·假 high | 两档**最大值**都 < 20 字   | `reasoningEfforts: false`（摘档位）     |
| 关不掉     | 关 ≥ 100 字、开与关同量级  | `reasoningEfforts: false`（摘档位）     |
| 方向相反   | 关 ≥ 100 字、开 < 关的一半 | `reasoningEffortsSwapped: true`（对调） |
| 测不准     | 两档区间重叠               | **不动**                                |

本次落地：**摘 11 条、对调 4 条**（清单见 `src/model-caps.ts` 的条目注释）。

**「两毛病并存」的按摘处理**（维护者拍板）：有 4 条既关不掉、方向又反
（`trae/glm-5.2`、`trae/glm-5.3-flash`、`trae/kimi-k2.6`、`trae/step-5-preview`）。
两条口径在这里给出相反动作 —— 取「摘」：对调只修一半（关仍然在思考），
而摘掉不给用户任何错误预期。

**调不通的 18 条保持现状**（维护者拍板）：区域未注册 7 条、模型不被允许 9 条、
上游服务异常 2 条。**没有加黑名单** —— 理由见下。

## 替代方案（为什么没这么做）

- **按单次测量直接改** —— 否。会重犯上一版的错（见上表）。
- **「测不准」也当「没差别」摘掉** —— 否。测不准可能其实是真开关，摘了是**丢功能**；
  维护者口径也确认「先留观察」。
- **给调不通的模型加全局黑名单（从选择器里藏掉）** —— 否，三层理由：
  ① 失败原因是**账号 / 区域相关**（你的号在 WorkBuddy CN 区、ZCode 号没这些模型权限），
  别的用户可能能用，全局黑名单会替他们做错决定；
  ② 本仓对该现象已有口径：「**端点声明 ≠ 实际可调用**……属上游限制，**别当路由 bug 去查**」
  （[channels/AGENTS.md](../../src/channels/AGENTS.md)）—— 加黑名单等于改这条口径；
  ③ 上游自己会给出可读的报错，用户选中失败的代价是**一次报错**，而不是「模型凭空消失」。
- **对调用「换界面文案」实现（把 High 改叫 Low）** —— 否。档位名是宿主契约
  （只有 `off` / `high` 两个键），改文案是假修：请求参数没变。
- **窗口是必填，为挂标记给 Trae 平台模型补窗口** —— 否。那是**编一条没有出处的数据**
  去换一条有出处的数据，而且会**静默**把宿主兜底 262144 改成写的那个值。
  改成「`contextWindow` 可选」之后，档位与窗口各按各自的证据轴走。

## 一个被本次复核纠正的误读

上一轮我把 `zcode/glm-5.3` 的一条
`400 code 1210 "always engages in thinking and cannot be disabled"` 当成了**模型属性**。
单独复测（`none` / `off` / `low` / `high` 四种词各发一遍）：**全部 200、全部 0 字思考**
—— 那条 400 是上游/渠道插件的**瞬时状态**。

**教训：上游单次报错不能当模型常性。** 要判「模型能不能关掉思考」，只能看
**多次请求的思考内容**，不能看一次报错文案。
