# 决策：老机器托管配置缺 `server.host` 时自动补齐（2026-10-10）

状态：生效

## 问题

CPA 的 `server.host` 是**安全边界**：缺这行时 CPA 监听 `::`（所有网卡），
2026-10-04 实测局域网内 `http://<内网 IP>:8317/v1/models` **不带任何鉴权返回 200**。

插件的生成逻辑（`renderConfig`）只在「配置文件不存在」时写 —— 于是**只有全新安装
的机器是安全的**，已经跑过一次的老机器配置里没有这行，升级插件也救不了
（生成逻辑不碰已存在的配置）。本机当时已手动补写，其他老机器一直暴露着。

## 决策

**`boot` 生命周期里、CPA 未运行时，调用 `patchServerHost()` 自动补齐。**

三个板（维护者 2026-10-10 拍板，均按 PLAN §2.1 前置调查的建议）：

1. **自动补，且只补「缺失」** —— 配置里已有 `host`（哪怕值是 `0.0.0.0`）是用户
   自己的决定，一律不动；没有 `server:` 段的配置是看不懂的形状，**放弃且不改文件**。
2. **挂在 `runBoot`，不挂 `SetupSession.ensure`** —— 见下方「调查修正」。
3. **与 `access.api-keys` 收口分开** —— 补 host 是关已经敞开的门，风险低、可独立
   验收；api-keys 会立刻影响调用链（DSH 侧必须同批带 header），属改行为、另行走
   §2.9。混在一起会让急事被拖住。

### 调查修正（对原设想的一处推翻）

PLAN 原设想挂「`SetupSession` 的 ensure 语义」。查证结果：`autoInstall` 只在
`inspect().missing` 非空时才动手 —— **老机器环境齐全时这条路径根本不会跑到**，
挂上去恰好漏掉最需要修的那批机器。所以实际挂在 `runBoot` 的启动序列里
（「补环境」之前）：`portBusy` 为假（CPA 未运行）时执行。

### 实现纪律（与 `patchModelAlias` 同款）

- 外科手术式：找到 `server:` 头行 → 段内**没有** `host:` 才在头行后插一行
  `host: "127.0.0.1"` → 落盘。其余内容一个字节不动。
- ⚠️ **插进去的那行必须跟随段内既有键的缩进，不能写死** —— 见下方「首日事故」。
- 找不到锚点（无 `server:` 段 / 头行带行内内容）→ 放弃，**绝不重写整份文件**
  （那会连密钥哈希带注释一起冲掉）。
- `host:` 锚定在 server 段**内** —— 别的段下的同名键不算数。
- 朴素正则、零 YAML 依赖（插件保持零 npm 依赖）。

### 首日事故：写死 2 空格缩进把 CPA 打瘫（2026-10-10）

**落地当天就真机踩中，症状是「CPA 连不上、面板全空」。**

- **事实**：CPA 保存配置时用 **4 空格**缩进（它自带的 `config.example.yaml` 就是
  4 空格），而 `renderConfig` 写的是 2 空格。于是**被 CPA 回写过的托管配置整份是
  4 空格** —— 而首版补丁把 `  host: "127.0.0.1"`（2 空格）硬插进 `server:` 段。
- **后果**：`host` 与 `port` 之间出现**缩进跳变**（2 → 4）。YAML 里 `host: "..."`
  已是标量，紧跟其后的更深缩进键无处可挂 ⇒ **整份配置非法、CPA 拒绝启动**：
  `yaml: line 19: did not find expected key`（真机 `startup.log` 原文）。
- **为什么零信号**：坏掉的那份配置**看起来只是缩进不一样**，插件侧不解析 YAML、
  不校验自己写出的配置能不能被对端读 —— 唯一的表现是 CPA 静默起不来。
- **修法**：取 `server:` 段内**第一个非注释键**的缩进，用它写新增行；段为空（没有
  既有键可跟随）时退回 2 空格。
- **判据**：`tests/setup-config.test.ts` 的 `patchServerHost` 组 —— 含一条 4 空格
  场景（补进去的行必须是 4 空格、段内缩进必须唯一）。已验证该用例在旧写法下**变红**。

## 替代方案（强制）

- **挂 `SetupSession.ensure` / `autoInstall`**：老机器 `missing` 为空、路径不跑，
  修不到目标人群 —— 调查推翻。
- **没有 `server:` 段时新建整段**：那是在改一份我们没把握理解的配置；放弃的代价
  只是「这类机器保持原状」，重写的代价是可能毁掉用户配置。宁可保守。
- **提示用户手动补**：老机器用户根本不会打开面板看提示；一个安全默认值不该
  依赖用户动手。
- **与 api-keys 同批收口**：api-keys 加上的瞬间，DSH 调用侧若没同批带 header
  就**先把自己挂了**；绑在一起让「关暴露面」这件急事被拖住。分开后各自独立验收。

## 影响

- 时序约束：**只在 CPA 未运行时补**（`!portBusy`），且在 `runtime.ensure()` 之前 ——
  CPA 运行中持有配置文件且保存时会回写，运行中改它是竞态。CPA 常驻外部管理的
  机器（端口一直被占）不会被碰到，那也不是我们托管的那份配置在服务。
- 补上后 CPA 下一次由插件拉起时即监听 `127.0.0.1`；已在本机复验「已有 host →
  一字节不动」路径。
- 判据：`tests/setup-config.test.ts` 的 `patchServerHost` 组（补上 / 已有不动 /
  本就安全不写 / 无段放弃 / 文件不存在不创建 / 别段的 host 不算数 / 头行带内容放弃 /
  **4 空格场景** / 空段退回 2 空格）。
