# 决策：P7 收窄成「纯物理迁移」，net.ts 归入 setup 层（2026-10-05）

状态：生效

## 问题

原 P7 是三件**结构**改动：`net.ts` 的代理与 HTTP 分开、状态文件写入改成「单入口读改写」、
模型路由模块拆掉时钟依赖。它们改善可测性，但都落在宿主半端最热的路径上，
所以一直挂在已知局限里缓办（[架构说明](../../docs/ARCHITECTURE.md) §7）。

缓办的理由不只是「风险高」，更是**没人需要它们**：三处都没有已知的静默失败指着。
照原样做等于在没有安全网的地方搬结构；而「缓办」又让这三件事一直挂在局限清单里，
看不出边界到底该怎么划、做完算不算完。

## 决策

P7 收窄成**纯物理位置整理**：只搬文件位置，不改任何行为。六条纪律：

1. **一次移动 = 一个提交 = move-only** —— 符号原样搬，只改 import 路径；不许顺手改行为、
   签名、整理 import。判据是 `git diff --cached --stat` 只能有 rename 与说明符。
2. **先锚定边界再动文件** —— 目标目录的规则**先**写进守卫与 `src/AGENTS.md`，再搬。
   否则搬的过程中越界**零信号**：构建期与测试期都不报错。
3. **目标位置由既有尺子推出，不新开目录** —— 尺子见 §3.1「一起改的放一起 / 不一起用的
   别绑一起 / 漂了报不报错」；新增目录要与「有独立规则可写」对齐（§3.1 已裁
   `http/`、`host/`、`domain/` 一律不建）。
4. **`git mv` 保历史；分层 relocate 不加 shim** —— shim 只用于**层内**移动
   （旧位置留 re-export，本批 PR 内删掉）。
5. **每步六条判据全绿才继续** —— typecheck / layering / test / artifacts / 旧 shim 在 /
   新文件在；任一条红就**回滚这一步**再查。
6. **一个文件一批，一批一 PR**，按风险递增 —— 一批多文件时，某一步红了分不清是哪个文件
   引起的，回滚粒度也会变粗。

**第一件（本次）**：`net.ts` 迁入 `setup/`。它唯一的消费者是 `setup/download.ts`，
按「一起改的放一起」两者是同一件事；它还是本层里**零仓内依赖**的文件（只用 `node:`
内置），因此风险最低、适合试点。

**不属于 P7 口径**：`net.ts` 的**拆分**（代理 vs HTTP）、`state.ts` 单入口读改写、
模型路由时钟注入 —— 这三件都要改行为或签名，各自立项，并按 §7 的要求**先补判据再动结构**。

## 替代方案（强制）

- **照原方案做三件结构改动**：没有已知静默失败指着，却要动最热路径，而「读改写」的
  并发判据还不存在 → 否决：先只搬位置，判据补上再谈结构。
- **新建 `src/net/` 或 `src/http/` 放 `net.ts`**：与 §3.1「新增目录要有独立规则可写」
  冲突 —— 一个文件撑不起 `AGENTS.md` + `README.md` 双件，概念数量不等于目录数量 → 否决。
- **留在 `src/` 根**：根目录已经混着基础模块、能力模块与传输层；再留一个只被 setup 用的
  工具，等于要求读者记住「它其实属于 setup」 → 否决。
- **搬进 setup 的同时把代理与 HTTP 拆成两个文件**：一次做两件事，move-only 判据失效，
  而拆分正是「先补判据再动结构」的那一条 → 否决，另行立项。
- **给旧路径留 re-export shim**：分层移动下 shim 会把 `src/` 根的规则重新适用到
  `net.ts` 上，等于守卫自己骗自己，而唯一调用点同批就改完了 → 否决。
- **一次把 `src/` 根搬完（省 PR 轮次）**：一批多文件，某步红了分不清是哪个文件引起的
  → 否决，一个文件一批。
- **不先立守卫规则，直接搬**：搬完再补规则时，「它为什么不能引 `gateway`」已经没人记得，
  规则容易被写成「当前就是这么写的」而不是一条边界 → 否决，顺序固定为「先规则后移动」。

## 影响

- `setup/` 现在有守卫规则 `setup-no-outer`：本层不得引用 `index` / `boot` / `route-table` /
  `routes` / `route-registry` / `gateway` / `runtime` / `ops/**`。理由是事实层面的：
  环境准备下的都是**公开 release**，不是 CPA 的 API —— 走 `gateway` 会同时要求管理密钥
  与运行态前置，两件事都错。
- **行为零变化**：`net.ts` 的 diff 是 0 字节，唯一改动是 `setup/download.ts` 的一行说明符。
- 文档换承载处：`src/README.md` 的模块条目改由 [`src/setup/README.md`](../../src/setup/README.md)
  承载（同一事实只写一处），前者保留一行指针。
- 判据：`pnpm check` 全绿（`check:layering` 7 条规则、348 用例）+ 六条判据逐条核对 +
  `git diff --cached --stat` 的 move-only 形状。落地与验收记录见
  [PR #25](https://github.com/cslkkl/dsh-cpa-switch/pull/25)。
- **P7 到此收官（2026-10-05）**：纯物理迁移只有 `net.ts` 一件。其余候选都不是纯位置问题 ——
  `src/` 根剩下的是基础登记处（`ids` / `paths` / `state`）、装配与传输层
  （`index` / `boot` / `route-table` / `routes` / `gateway` / `runtime` / `process`）、
  以及判据类；判据类留在根是因为「判据层」目录按 §3.1 不建，由守卫的清单规则守着。
- 两件改行为的（`state.ts` 单入口读改写、模型路由时钟注入）**已立项、未开工**：
  见 [PLAN §2.9](../../docs/PLAN.md)。**先补判据再动结构** ——
  「读改写」先要并发用例，时钟注入先把等待间隔变成可断言的判据。
