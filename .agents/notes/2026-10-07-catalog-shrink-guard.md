# 决策：目录护栏 + 有限重读（2026-10-07）

状态：生效

## 问题

第 1 批真机重启**三次里有两次**出现：

| 现象                                                       | 何时自愈        |
| ---------------------------------------------------------- | --------------- |
| 选择器里只剩 1 个模型（`WorkBuddy · deepseek-v4.1-flash`） | 几秒后 / 点一下 |
| 选择器里只剩**一个渠道**的模型                             | 同上            |
| 正常                                                       | ——（第三次）    |

根因不是「读得慢」，而是**读到残缺目录之后把它当完整写进了磁盘缓存**：

1. CPA 刚起或增量重建时，`/v1/models` 与逐凭据供给面都可能在分批加载；
2. 插件读了一次，旧判据只问「**非空吗**」—— 非空就写盘；
3. 那份缓存是**每次启动先推回去**的，于是残缺可能变成**永久**的。

## 为什么前五轮都修不掉

前五轮改的都是**「多久算读完了」这个阈值**：

| 调法 | 结果                                        |
| ---- | ------------------------------------------- |
| 调松 | 半成品当成品 → 推出错的（1 条模型、错归属） |
| 调严 | 一个坏渠道把门卡死 → 全部模型消失           |

这个阈值**根本调不出来**，因为「还在长」与「永远长不出来」在时间上不可区分
（[启动不等读那篇](2026-10-06-startup-does-not-wait.md)已经把这条讲透了）。

## 决策

**不再问「齐了吗」（答不了），改问「比上一份差吗」（答得了）。**

关键事实：CPA 的模型目录只会因**加号**增长（加号、加渠道、重启加载），
不会自己缩小，除非删号或换配置。

### 1. 目录护栏 = 写盘与推送之前的最后一道闸

- 比较新算出的清单与 `lastGood`（上一份成功快照）；
- **少了行 ⇒ 丢掉这一份**：不写盘、不写别名段、继续用上一份；
- 被挡住时走既有的 `degrade`（回推上一份），不卡死。

### 2. 比较单位是**（渠道，模型裸名）**，不是行 id

⚠️ 这条是设计判据时才发现必须钉死的：同名模型被多渠道供给时行 id 是**渠道别名**
（`wb/glm-5.3`），而**一个渠道消失后别名本身就不再生成了** —— 剩下的那个渠道
的行会从 `qoder/glm-5.3` 变回裸名 `glm-5.3`。拿行 id 比，就会把这次**合法**的改名
当成「qoder 少了 glm-5.3」而拦下，于是「跳过坏渠道」这条逃生口**根本走不通**
（变异验证 M8 钉住了它）。

用「渠道 + 裸名」比则不受别名形态影响：那个模型**还由那个渠道供着**，
只是它现在不需要别名了。

### 3. 逃生口：按渠道放行，不是整体放行

缩水有两种 —— **读残了**（该拦）与**合法地少了**（不该拦）。后者有两个来源：

| 来源           | 信号                    | 含义                   |
| -------------- | ----------------------- | ---------------------- |
| 渠道永久读失败 | `ReadySnapshot.skipped` | 读不出来（404 / 失效） |
| 凭据不可用     | `ReadySnapshot.dropped` | 读得出来但不该供给     |

两者都让清单**合法地**变小；只认其中一个，另一个场景就会把删号 / 禁用卡死。

⚠️ 放行**只覆盖那个渠道**。整体放行的话，用户只要有一个长期禁用的号，
护栏就永久失效 —— 那正好把本批要治的病放回来。

### 4. 有限重读：由迹象触发、有上限、不常驻

被护栏拦下之后按 `2s → 5s → 15s → 30s` 再读几次，**四次封顶**：

| 时机            | 排不排   | 为什么                                              |
| --------------- | -------- | --------------------------------------------------- |
| `boot`          | 排       | 首次装 / CPA 刚起，凭据还在分批加载                 |
| `setup`         | 排       | 刚重新生成配置、拉起 CPA —— 就是它引起的            |
| `oauth`         | 排       | 加号 / 删号，会改注册表                             |
| `config-reload` | **不排** | 只改 DSH 自己的配置（切语言等），CPA 一个字都不会变 |

收场只有两种：**重读拿到更好的** → 立刻收场；**四次都没读到更好的** → **放行**。

⚠️ 放行是**必需**的：一次**真的**缩水（用户删了号、而这次没留下任何 skip 信号）
若被护栏永远拦住，用户看到的是**已经删掉的模型**一直在选择器里，比少显示更糟。

⚠️ 放行时**不写别名段**：那一份按定义是可疑的（护栏拦过它），而别名段是整段替换 ——
写下去可能把 CPA 里还活着的别名删掉。清单是自愈的，别名不是。

### 5. 行归属要跨重启活下来

护栏按渠道放行需要「每一行属于哪个渠道」。启动时 `lastGood` 来自磁盘缓存，
所以那份归属表也写进缓存（`cachedRoutesFile.channels`）。

⚠️ **没有 bump 缓存版本**：判别标准是「老文件会不会被**误读**」——
老缓存缺 `channels` 时解析成空表，护栏退化成**保守路径**（认不出归属 = 按缩水处理），
语义仍然正确，只是「删号」那类合法缩水要多等一轮重试。bump 反而会把一份
**完好可用**的缓存作废，把「首次启动什么都没有」那个老痛点请回来。

## 替代方案（强制）

- **继续调「多久算读完」的阈值**：前五轮的失败方式，且这个阈值在原理上调不出来
  （「还在长」与「永远长不出来」时间上不可区分）→ 否决。
- **整体放行（handoff 字面写法）**：本轮只要有渠道被跳过，护栏就整个不生效。
  实现最简、不动缓存结构，但**用户只要有一个长期禁用的号，护栏就永久失效** ——
  那正好把本批要治的病放回来 → 否决，改为按渠道放行。
- **不设凭据逃生口（一切合法缩水都等重试用完）**：最严、代码最少，
  但删号 / 禁用后要等约 52 秒才反映，而那是**用户刚刚主动做的事** → 否决。
- **逃生口按「本轮有渠道被跳过」判（不比对上一份）**：`oauth` 删号后凭据是
  **从列表里消失**的 —— 它既不进 `skipped` 也不进 `dropped`，本轮**没有任何信号**。
  所以「删号」只能靠「重试用完 → 放行」兜住 → 否决（该口径覆盖不了它自己的例子）。
- **比较单位用行 id**：见决策 §2，别名改名会被误判成缩水，
  「跳过坏渠道」的逃生口当场失效 → 否决。
- **护栏只挡写盘、不挡推送**：那样用户**当下**看到的就是那份残缺清单
  （正是实机症状），护栏等于没做 → 否决。
- **缓存版本 bump 到 2**：老缓存本来能被正确解释（缺字段 = 保守路径），
  bump 只会白白作废一份好缓存 → 否决。
- **重读链做成常驻轮询 / 无上限**：会把仓库「恢复逻辑挂事件、不挂时机」这条口径
  反过来，且 52 秒之后仍不收敛说明它不是暂时现象 → 否决。
- **重读挂在 `config-reload` 上**：它**每次设置写入**都会到，挂上就是无脑轮询，
  与「由迹象触发」直接矛盾 → 否决。
- **`lastGood` 用「模型数量」比**：数量持平而集合不同（少一个、多一个）时
  它判「没变」，而换掉的那个可能正是用户选中的那条 → 否决，比集合。
- **给 `settled()` 之外再加一个「重读进度」接口**：只有判据与收尾需要它，
  暴露更多状态等于把内部时序变成契约 → 否决（只交一个 `settled()`）。

## 影响

- **收益**：残缺目录不再被当成事实（既不写盘也不推给用户）；
  合法的缩水（删号 / 禁用 / 坏渠道）仍然立刻反映；一次真的缩水最多晚 52 秒收敛。
- **代价**：多一张行归属表进缓存；`refresh` 的返回面从裸函数变成带 `settled()` 的
  可调用对象（现有调用点 `ensureRoutesFresh(trigger)` 逐字不变）；
  启动时若目录**真的**变了，用户会先看到上一份、最多 52 秒后更新。
- **判据**：`tests/route-registry.test.ts` 的「目录护栏与有限重读」**9 例**
  （7 条要求 + 2 条配对：按渠道放行只覆盖被跳过那个渠道、`dropped` 逃生口）。
  **11 条变异逐条验证过**，每条至少一条判据转红：
  去掉护栏 / 去掉按渠道放行 / 整体放行 / 不排链 / 无脑轮询 / 重试无上限 /
  允许叠加两条链 / 比较单位退回行 id / 重试用完不放行 / 被挡住照样写盘 /
  删掉 `dropped` 逃生口。
  ⚠️ **最后一条是变异验证发现的缺口**：原先只覆盖 `skipped`，
  把 `dropped` 从放行名单里删掉时**一条都不红** —— 逃生口等于裸奔一半，
  于是补了「凭据不可用（面板禁用）」那条配对判据。
- ⚠️ **顺带修掉一处判据污染**：「思考档位声明」那一组原先**没隔离 `DSH_HOME`**，
  于是会去读开发机**真实**的 `storages/cpa-panel-routes.json` 当 `lastGood`。
  在护栏之前看不出来（慢路径那份总是最后推的），加护栏之后**当场转红**。
  已补 `beforeEach` 隔离 —— 不隔离就是「本机绿、CI 红」，与代码对不对无关。
- **真机验收**：需重启 DSH。验收点是**三次重启里那两次残缺不再出现**，
  且**删号 / 禁用后清单仍立刻变小**（逃生口没把合法缩水卡住）。
