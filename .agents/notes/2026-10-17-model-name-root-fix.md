# 决策：推送模型名去掉渠道前缀（根修）（2026-10-17）

状态：生效

## 问题

推给宿主的模型行，`name` 一直是 `` `${渠道展示名} · ${裸名}` ``（`WorkBuddy · glm-5.3`，
出自 `displayNameOf`）。这个形态是 2026-10-12 分组化、2026-10-13 修「弹窗里每一行都叫
同一个词」时定下的（见[分组决策](2026-10-12-model-selector-grouping.md)与
[可见性决策](2026-10-13-model-visibility-in-panel.md)的事故四）—— 但它是一笔债：
选择器从分组化那天起就按 provider 分组，**组标题（`CPA Switch · WorkBuddy`）已经
承载了渠道**，每一行再把渠道念一遍就是同一句话说两遍；`/model` 命令弹窗的行与
面板勾选行的 `label`（与 `name` 同源）同样冗余。

修法有两条路：在浏览器半端把前缀**剥掉再显示**（客户端治标），或者从推送侧把
`name` 改成裸名（根修）。选根修之前必须先回答维护者的那句话：**去掉前缀，会不会「窜」？**

## 决策

**`displayNameOf` 直接返回 `row.bare`**（[src/route-registry.ts](../../src/route-registry.ts)），
推送行的 `name` 与面板候选行的 `label` 都从它取 —— 一份实现、两处引用，同批改。
渠道信息由分组标题承载；composer 收起状态与菜单根行（不在分组里）的渠道上下文由
新槽位补回，见[双座位决策](2026-10-17-composer-slots.md)。

### 「会不会窜」的证据链：不会

`name` 是**纯展示载荷**，整条链上没有任何一环用它；身份从头到尾是 `providerId/modelId`：

- **本仓六条键逐一不沾 `name`**：① 路由解析用行 `id`；② 别名表按「裸名 + 渠道」
  收键；③ 目录护栏 `guardKeyOf` = `` `${channel}\u0000${stripChannelPrefix(id)}` ``；
  ④ 模型可见性隐藏键是（渠道, 裸名）；⑤ 去重键也是（渠道, 裸名）；
  ⑥ 磁盘缓存读回后 `name` **原样重推、不做任何比较** —— 所以不需要 bump
  `CACHED_ROUTES_VERSION`，代价只是「升级后第一次启动会先推一份旧形态名字的缓存」。
- **宿主侧全线按 id**：选择器行键 `providerId/modelId`；点选回填用 row id 反查
  provider/model 的 **id**，不解析名字；落库的会话选择投影只有
  `{provider, model, reasoningEffort}` 三个 id；提交校验 `resolveCallConfig({provider, model})`；
  适配器模型表按 id 建索引。宿主自己的 README 写明
  **「Directory names are presentation-only」**。

> 证据文件：`.probe/slot-research/name-blast-radius.md`
> —— ⚠️ 它是 `.gitignore` 排除的**本机调研件、不入库**（clone 后没有这个文件），所以
> 这里只写路径、不做链接：链接到不入库的文件等于全仓一处永久断链。
> 上面是它的自含结论；入库的判据见文末。

### 两处补不回来的代价（如实写）

去掉前缀后，宿主界面有两处**新槽位救不到**：

1. **composer 触发位的 `title` / `aria-label`** —— 宿主在渲染槽位**之前**就用
   `model.name` 把这两个串算好了（同一个字符串变量），且宿主 README 明说
   「trigger accessibility text」归选择器拥有。悬停与读屏从此只拿到裸名。
2. **`/model` 命令弹窗的搜索** —— 行有分组标题（渠道**看得到**），但搜索是
   `fuzzy-label` 模式、只把行标签（= `model.name`）交给匹配，**分组标题不进匹配**
   —— 打「workbuddy」搜不到该渠道任何一行。**看得到、搜不到。**

所以这条按「行为变更」对待，不是「纯显示变更」。

### 七条反向断言同批改裸名

`tests/route-registry.test.ts` 里七条「清单里**不许出现**某某」的反向断言
（`not.toContain('Kimi · kimi-k2.8')` 这类）按旧的 `渠道 · 名字` 形态书写 ——
根修后那个字符串**再也不会出现**，断言**永远为真**：一杆永远打不响的空枪。
而它们真正要看住的恰恰是「**别的渠道的模型混进这一轮清单**」（目录护栏按渠道
放行的反面）。同批改成裸名形态（如 `not.toContain('kimi-k2.8')`），空枪重新咬合 ——
不改的话护栏相关的这层哨兵**静默失效**，且全绿。

## 替代方案（强制）

- **客户端剥离**（浏览器侧把 `name` 的前缀剥掉再渲染）：**否**。那是「同一份显示名
  两处各算一遍」—— 正是[事故四](2026-10-13-model-visibility-in-panel.md)刚修完的病根；
  且浏览器半端不许引宿主模块，剥前缀的渠道知识只能再抄一份到客户端。
- **只靠 label 槽补渠道、`name` 保持前缀**：**否**。`option` 行、`/model` 弹窗、
  面板勾选行的冗余照旧，债没还；新槽位是「增益」，不是继续背债的理由。
- **不动**：**否**。分组已经存在，冗余从「补上下文」变成了「同一句话在界面上说两遍」。

## 影响

- 推给宿主的 `name` 与面板勾选行 `label` 一起变裸名（两侧同源，一起变是预期）；
  渠道上下文仍有四处承接：composer 分组标题、`/model` 弹窗分组标题、子代理设置卡、
  ACP 选项组名 —— 它们读的是 provider 显示名，不依赖新槽位。
- **一次性过渡推**：重启后磁盘缓存里旧形态的 `name` 会先原样推一轮，
  随后被第一轮真读覆盖 —— 预期内，不是回归。
- 判据：`tests/route-registry.test.ts` 新增「推给宿主的 name 就是裸名」一组 ——
  ① `name` **逐字** `toBe('glm-5.3')`（不是 `toContain`：那个写法对
  `WorkBuddy · glm-5.3` 也成立，钉不住根修）；② 无渠道展示名；③ 无分隔符；
  ④ **`id` 一字不动**（路由身份，根修只许动展示名）；⑤ 分组身份仍在。
  变异验证的做法（与事故四同一条路数）：把 `displayNameOf` 改回前缀形态，
  新断言应**当场变红**、其余用例全绿 —— 以此证明判据真的咬住了这次的改动。
