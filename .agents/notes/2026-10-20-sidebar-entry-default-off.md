# 决策：侧栏入口默认「关」（2026-10-20）

状态：生效

## 问题

`0.18.0` 把「侧栏入口」开关交到用户手里，但默认值是**开** —— 装上插件，侧栏立刻多一行。
维护者的判断是：**侧栏不该被插件默认占位**，要的人自己打开。

这不是「默认值随便选」的小事，两边的失败形态不对称：

- 默认**开**、用户不想要 → 侧栏永久多一行，他得先找到面板、再找到底部那个开关；
- 默认**关**、用户想要 → 他从插件页进一次面板，按一下开关，之后常驻。

面板本来就有插件页入口，所以「默认关」不会让任何人**找不到**这个插件。

## 决策

`sidebarEntry` 的默认值与兜底方向都是 **`false`**：

| 位置                                          | 行为                       |
| --------------------------------------------- | -------------------------- |
| `src/state.ts` 的 `defaultPanelPrefs()`       | 首次安装 / 文件丢失 ⇒ 关   |
| `src/state.ts` 的 `readPanelPrefs()` 脏值分支 | 字段不是布尔 ⇒ 关          |
| `src/state.ts` 的 `readPanelPrefs()` 来源分支 | `source` 不是 `panel` ⇒ 关 |
| `src/client/sidebar-visibility.ts` 的未读到态 | 还没读到偏好 ⇒ 关          |

读到「开」之后才 `slots.inject` 那一行 —— 那一次推送来自宿主真实值，不是猜的；
用户按过开关就以文件为准（`source: 'panel'` + 布尔），升级不会把他的选择冲掉。

## 替代方案（强制）

- **保持默认开**：`0.18.0` 的做法。否掉的理由是「替用户决定侧栏长什么样」——
  侧栏是全宿主共用的一列，插件只是其中之一。
- **坏值 / 读失败仍按开（开机即显示）**：会造成**方向不一致** —— 文件说关、坏一次就冒出
  一行；用户会把它读成「开关失灵」。默认值与兜底必须同向，否则一次读失败就是一次界面撒谎。
- **干脆不要侧栏入口**（回到 `0.17.0` 之前）：维护者要的是「可以常驻」这个能力，
  不是「一定常驻」；整条摘掉等于把选择权也拿走。
- **默认关但首次进面板时弹一句「要不要固定在侧栏」**：多一次打断，而开关就在面板底部一行里，
  找得到；等有第二处偏好再说。

## 影响

- 收益：装完不动侧栏；想要常驻入口的人按一次开关，之后跨重启保持。
- 代价：想要侧栏入口的人**必须自己按一次**（这是本条决策明确接受的代价）。
  从 `0.18.0` 升级上来、且没按过开关的用户：侧栏那一行会**消失**（文件不存在 ⇒ 新默认）。
- 判据：`tests/ops-prefs.test.ts`（默认关 / 脏值关 / 非 panel 来源关 / 文件为开时照文件）、
  `tests/sidebar-visibility.test.ts`（未读到为关 / 值没变不通知 / 取消订阅）；
  产物断言三条不变（disposer 被接住、走 `panel-prefs`、写回读值喂给状态）。
- 接线：`src/state.ts`（默认与兜底）、`src/client/sidebar-visibility.ts`（未读到态）、
  `src/ops/prefs.ts`（域注释）、`src/client/index.tsx`（首屏挂载时机）。
