# 决策：渠道知识单一来源，启用清单改由磁盘决定（2026-10-05）

状态：生效

## 问题

同一份「有哪些渠道」的知识登记在**四处**，而四处互相矛盾：

| 位置                                   | 认哪些渠道                       | 用途                                    |
| -------------------------------------- | -------------------------------- | --------------------------------------- |
| `src/adapters.ts`                      | workbuddy / trae / qoder / zcode | 面板、能力、路径                        |
| `src/model-alias.ts` 的前缀表          | 上面四个 + kimi + mimo           | 同名模型的别名前缀                      |
| `src/route-registry.ts` 的展示名与顺序 | 上面六个                         | 模型选择器里的展示                      |
| `src/setup/config.ts` 的启用清单       | 上面四个 + mimo（**缺 kimi**）   | 写进 `config.yaml` 的 `plugins.configs` |

每一种单独看都自洽，所以**漂了不报错**。真正的后果只有一个方向是致命的：
kimi 能被算进别名表、能被推成模型路由，却从来没被写进 `plugins.configs` ——
按上游语义，那个渠道在 CPA 侧**未激活**，账号接口一律 404。

还有一处渠道差异漏在注册表之外：`zcode` 的模型目录是 `/models`（其余是
`/models/groups?refresh=1`）、成长中心只有 workbuddy 有 —— 这两条是 `operations.ts`
里的内联分支，正好违反「渠道差异集中在一处」。

## 决策

- 新增 `src/channels/`：**一个渠道一个 spec**（`workbuddy.ts` / `trae.ts` / `qoder.ts` / `zcode.ts`）
  \+ `registry.ts` 作为唯一查询入口。`ChannelId` 由清单推导，不再手写联合类型。
- 全部派生：面板渠道表、模型路由的展示名与顺序、别名前缀、写操作路径、模型目录、成长中心。
- **spec 只写差异**：四个渠道同构的路径（`/accounts`、`/config`）做成注册表的模板函数。
- **托管 / 非托管分开**：kimi 与 mimo 不由本插件管理，只在注册表里登记**展示名**
  （`UNMANAGED_LABELS`），不登记能力与路径。别名前缀的兜底是「原样小写」，
  所以它们连前缀都不需要登记。
- 生成 `config.yaml` 的启用清单 = **磁盘上实际存在的 dll**（`listPluginIds()`），
  由 `prepare()` 在插件解压就位之后传给 `renderConfig`；手写清单删除。

## 替代方案

- **保留四处清单，只加一致性测试**：测试能发现矛盾，但新增一个渠道仍要改四处 ——
  治标，而且测试本身就是第五处登记。
- **把 kimi / mimo 也做成一等公民**（补 spec、进面板）：维护者裁决为否 ——
  本插件不管这两个渠道。真要管时加一个 spec 即可，注册表已经留好位置。
- **启用清单保留手写、把 kimi 补上**：仍是一份会漂的清单，只是这次恰好补齐；
  下次上游渠道包加一个 dll，同样的静默失败会再来一次。
- **按「渠道包理论上提供哪些 dll」写常量**：那是上游的事实，不是本机的；
  解压之后磁盘就在手边，读它比抄它准。

## 影响

- 新增渠道 = 新增一个 spec 文件 + 在 `CHANNELS` 挂一行；面板、路由、别名、生成配置全部自动跟上。
- 启用清单跟着磁盘走：装了 `kimi.dll` 就会启用 kimi（这是修复，不是放宽 ——
  多写一个不存在的 id 本来就无害）。
- 渠道层多一条分层规则 `channels-pure`（只许依赖契约与自身），
  纯判据（如 `model-alias.ts`）允许依赖它。
- `adapters.ts` 删除；`tests/adapters.test.ts` 改名 `tests/channels.test.ts`。
