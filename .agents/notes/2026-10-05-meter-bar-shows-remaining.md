# 决策：额度进度条画「剩余占比」，不画「已用占比」（2026-10-05）

状态：生效

## 问题

账号卡的进度条恒为**成功色（绿）**，但宽度按 `used / size` 画 —— **用得越多绿得越多**。
绿色在界面里直观读作「还有 / 可用」，于是这条的视觉含义和它想表达的意思**正好相反**：
一个快用光的号看起来最「健康」，一个满额的号看起来最空。

2026-10-05 真机验收时由维护者发现。这是**历史设计**，不是本轮边界重构引入的。

## 背景：条的位置与颜色都是钉死的

进度条住在**槽位 4**（`meterSlot`，18px），槽位语义被 F41 钉成「**只放进度条**」；
颜色是 `--dsw-alias-state-success-primary`，由 `tests/card-slots.test.ts` 钉住
（「保持成功色，不按阈值变色」）。

所以「改含义」只能从**分子**入手 —— 位置与颜色都不该动。

## 决策

`meterDecision` 的 `percent` 改成 **`remain / size`**：

- **满格 = 一点没用，空 = 用光** —— 与绿色「可用」的读法一致；
- 颜色不动（仍是成功色，仍不按阈值变色）；
- 「已用」那个数**照旧单独显示**（`hasUsed` 不变），只是**不再参与条宽**；
- 夹到 0–100：`remain > size`（赠送额度）顶格，`remain < 0` 不画负宽度；
- ⚠️ `remain` 不是有限数时**不画条** —— 与原判据同一把尺子
  （`typeof === 'number' && Number.isFinite`），画 0% 等于替上游说「剩余 0」。

判据仍在 `meterDecision`（纯函数），用例在 `tests/meter-text.test.ts`。

## 替代方案（强制）

- **改颜色（把条改成表示「已用」的颜色，如 warning）**：
  绿色本来就该表示「可用」，把它让给「已用」等于把语义反着钉死；
  而且卡片里还有一处绿（选中绿环），两处绿色会各表示一件事。
  改分子只有一个地方，改颜色要动 token 与槽位判据两处。
- **保留已用占比，在条旁边加一行百分比文字说明**：
  `meterSlot` 的语义被钉成「只放进度条」，写字会让同一槽位
  「一会儿是条、一会儿是句子」—— 正是 F41 要拦的那种「顺手塞进去」，
  且 `tests/card-slots.test.ts` 会红。
- **画两条（剩余 + 已用堆叠 / 双色）**：
  槽位高 18px、且「一个槽位只含一种东西」；trae 没有 `used`，
  堆叠条在它那里永远缺一半，等于把渠道差异搬进了组件。
- **条改成从右往左填充（仍按已用）**：
  「已用越多条越长」这个直觉没变，只是换了方向，问题照旧。
- **不动，接受「绿=已用」**：
  与卡片上「已用」数字的直觉冲突已经由维护者在真机上确认是缺陷，
  留着等于每天误导用户。

## 影响

**收益**：

- 条的视觉含义与它的名字（剩余）一致 —— 一眼能看出「还有多少能用」；
- 与旁边「已用」数字构成互补关系（条 + 已用 ≈ 满格），两个信号不再互相打架。

**代价**：

- 习惯「从左往右累计已用」的读法要改：条**越短表示越接近用光**；
- `used` 与 `remain` 不一致的渠道（上游两边各说各的）以 `remain` 为准，
  此时条与「已用」数字不再严格互补。

**未解决**（另案）：

- zcode 实测 `used: 0`、`size` 与 `remain` 相等 → 条满格。
  在「无法从插件侧区分『用户没用过』与『上游不上报』」之前，照实显示。
