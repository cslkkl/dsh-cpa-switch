# notes/ — 决策记录手册

记「**为什么这样定**」：当时的问题、选了什么、**试过什么但不行**、代价与收益。

## 命名

`<主题>-<日期>.md`，主题用 kebab-case，日期 `YYYY-MM-DD`。例：`2026-10-04-panel-slot-move.md`。

## 每篇的结构

```
# 决策：{标题}（YYYY-MM-DD）

状态：{生效 | 被取代 | 已否决 | 已归档}

## 问题
{为什么需要这个决策}

## 决策
{现在时描述 shipped 事实}

## 替代方案（强制）
- {方案 A}：为什么不行
- {方案 B}：为什么不行

## 影响
{代价与收益}
```

**第 3 行必须是状态行**，四值之一。`被取代` 必须跟指针行；`已归档` / `已否决` 必须跟一句话理由。

## 归档形态

**就地标记，不建 `archived/` 子目录**。失效的笔记保留原位置，只改状态行 ——
这样交叉引用不会断，历史也不会被挪走。

## 替代方案是强制的

不记录「被打败的选项」，下次必然会重诉同一个方案。这是本目录最有价值的部分。

## 不建索引

不逐篇列清单 —— `git log` 与目录树就是索引。本文件只写规则与结构。
