# 决策：首屏骨架与宽柔光带的参数（2026-10-07）

状态：生效

## 问题

打开插件配置页到数据到达之间有约一秒的空白：三处渲染的是同一句 `读取中…`，而它比真实内容矮得多。

代价不只是「不好看」：汇总三格与卡片网格是**一起**出现的，一句话换成它们时整块往下跳。

维护者的要求（原话）：

- 光带要**宽**，用**固定绝对像素**定义宽度，不要百分比 —— 「百分比会让光带在窄元素上塌缩成一条线」。
- 高光强度接近不透明，核心清晰可辨。
- **高光颜色就是背景色**，跟随主题，走主题变量，不硬编码 `#fff` / `#000`。
- 周期 2–3 秒、线性匀速、无限循环。
- **不错峰**：所有骨架元素同相位，不许有 `animation-delay`，有延迟变量一并删掉。
- 渐变两端留足羽化空间，避免硬边。

实现约束（维护者给定）：伪元素承载光带、容器 `overflow: hidden` 裁剪、光带从一侧外侧进入另一侧外侧移出、循环衔接处不停顿不跳变、**只对 `transform` 做动画**、保留 `prefers-reduced-motion` 降级。

## 决策

**扫光挂在「块」上，不挂在骨头上；宽度与位移靠「动画层与块同宽」解决，不靠百分比，也不靠 `background-position`。**

```
.skeletonBlock { --cpa-sweep-width: 160px; position: relative; overflow: hidden; }
.skeletonBlock::after {
  position: absolute; inset: 0;                      /* 层宽 == 块宽 */
  background-size: var(--cpa-sweep-width) 100%;      /* 光带：固定像素宽 */
  background-repeat: no-repeat;
  transform: translateX(calc(-1 * var(--cpa-sweep-width)));  /* 起点在左侧之外 */
  animation: cpa-skeleton-sweep 2.4s linear infinite;
}
@keyframes cpa-skeleton-sweep { to { transform: translateX(100%); } }
```

要点逐条：

- **为什么不在骨头上**（维护者 2026-10-07 指出「同一张卡片里两种截然不同的动效同时播放」）：
  骨头各自裁剪自己的光带，于是「光带宽度 ÷ 骨头宽度」决定了**动效的种类** ——
  比光带窄的骨头（36px 开关 vs 160px 带子、48px 实心核心）全程被盖住，只能**整块亮起再暗下**；
  比光带宽的骨头（248px 进度条）却能让带子完整进出，是一次**滑动**。
  行程也被带偏：层的 `translateX(100%)` 是相对骨头自身宽度，所以行程 = 光带宽 + 骨头宽，
  周期相同则快慢相差成倍（248px 那边 416px，36px 那边 196px）。
  改到块上之后：**全卡一道光、一个速度、一个节拍**，骨头只是被依次掠过。
- **难点只有一处**：伪元素上的 `translateX(100%)` 是相对**它自己**的宽度。层若设成光带宽度（160px），`100%` 就只走 160px，在宽块上永远出不去右侧。所以层取 `inset: 0`（与块同宽），光带只是层里一条 `background-size` 固定像素、不重复的背景 —— `100%` 这才等于「一整块块的宽度」。
- **宽度只写一处**：`@keyframes` 只写 `to`，`from` 取元素自己的基准 `transform`。于是起点与渐变共用同一个 `--cpa-sweep-width`，改宽度不必两处同改。
- **无缝**：起点与终点都在块之外（左侧外 / 右侧外），衔接处什么都看不见，所以没有停顿也没有跳变。
- **单相位**：没有 `animation-delay`，所有块共用同一条 keyframes。
- **只动 `transform`**：光带靠层位移移动，不碰 `background-position`。
- **颜色**：高光取 `--dsw-alias-bg-base`（亮=白、暗=深）+ `color-mix(… 65%, transparent)` —— 不透明的背景色带子读起来像一条硬边条纹。
- **降级**：`prefers-reduced-motion: reduce` 里只 `animation: none` —— 基准位本来就在块外，停住即不可见，骨架本身留着。
- **裁剪只在承载体上**：绝不加在真实 `.card` 上（`overflow: hidden` 会剪掉里面按钮与开关的焦点环）。

几何上**没有新尺寸**：骨架卡就是 `.card` 与六个真实槽位类，汇总用 `.summary` / `.summaryCell`，网格用 `.grid`。所以 222px 卡高、260px 列宽、12px 间距仍只有一份定义，数据到达是原地替换。

**范围**：骨架只盖「还没到的数据」。「添加账号」是**真按钮**、网格始终渲染，所以它不占位、也不参与占位卡数（早先版本为它多摆一张，那是错的）。

**骨头宽度照真实内容的常态摆，别夸大**：说明行常态只有一行（`factsOf()` 最多拼三项，且每项只在真有值时出现），`.facts` 的 36px 是给「认不出的上游档位名」留的**夹断容量**，不是常态 —— 骨架摆两条长骨头等于暗示「这里有两行长文」，那是在骗人（维护者 2026-10-07 指出）。

**分工**：TS 只声明「这是哪个槽位」（`data-shape`）与「几张骨架卡」（[skeleton-hint.ts](../../src/client/skeleton-hint.ts)）；宽高、颜色、周期、缓动全在 CSS。

## 替代方案

- **用百分比定光带宽度**（`background-size: 30% 100%`）：维护者点名否决 —— 窄块上塌成一条线。实测也正是如此：40px 宽的块上 30% 只有 12px。
- **扫光挂在骨头上**（本批的第一版）：**实机验收时被维护者否掉** —— 同一张卡里窄骨头呼吸、宽骨头滑动，两种动效同时播；行程还随骨头宽度变。这是本批最有价值的一条修正。
- **把伪元素本身设成光带宽度，用 `translateX(100%)` 走全程**：数学上不成立（`100%` 是自身宽度），在宽块上光带出不了右侧，循环衔接处会跳。
- **动 `background-position`**：位移看着更直观，但违反「只对 `transform` 做动画」；且它触发布局/绘制重算，`transform` 走合成层。
- **照抄宿主的骨架**（`--dsw-alias-bg-skeleton` 的 2 秒透明度脉冲）：宿主自己的加载骨架就是这么做的，一致性好，**但不是维护者要的效果** —— 要的是扫光，不是呼吸。
- **加载期继续显示那句文字**：改动最小，但留下约 82px 的位移（汇总行 69.5px + 12px 间距），而那正是这次要修的东西。
- **骨架卡数用常量**：改成本机记忆（`skeleton-hint.ts`）—— 因为「从缓存数账号」不可能成立（骨架出现的前提就是缓存为空），而常数在每台机器上都不准。

## 影响

- 首屏多约 3KB 的 CSS/JS（扫光段 + 骨架组件），无新依赖。
- 三处文字占位收成一处的骨架；`.blank` 随之只剩「失败」一义，改名 `.failed`。
- `loading` 这个文案键仍然被引用（骨架的读屏文案），所以不需要从两张表里删。
- 光带宽度是一个 CSS 变量，改它只碰一处。
- 多一份本机记忆（`localStorage` 的 `cpa-switch:accounts:<渠道>`）：只影响摆几张骨架卡，脏值一律回退兜底。
