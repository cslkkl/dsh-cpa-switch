## 批次 1 的定稿形态

**挂载点：扫光在「块」上，不在骨头上**（维护者 2026-10-07 指出）。

挂在骨头上时，光带宽度与骨头宽度之比决定了**动效的种类**，同一张卡里会同时播两种：

| 骨头         | 相对光带（160px，实心核心 48px） | 表现                                                    |
| ------------ | -------------------------------- | ------------------------------------------------------- |
| 开关 36px    | 比光带窄                         | 核心比骨头还宽 ⇒ 全程被覆盖，**整块亮起再暗下**（呼吸） |
| 进度条 248px | 比光带宽                         | 光带能完整进出 ⇒ **一次滑动**                           |

速度也被带偏：行程 = 光带宽 + 骨头宽（层的 `translateX(100%)` 是相对骨头自身宽度），
周期相同则快慢相差成倍（248px 那边 416px 行程，36px 那边只有 196px）。

改到块上之后：**全卡一道光、一个速度、一个节拍**，骨头只是被这道光依次掠过。
汇总行也照此办理（一道光扫过三格，而不是三条带子并排）。

**参数**：光带宽 160px（固定像素）、周期 2.4s、`linear` + `infinite`、
高光 `color-mix(in srgb, var(--dsw-alias-bg-base) 65%, transparent)`、
只动 `transform`、无 `animation-delay`、`prefers-reduced-motion` 只停动画。

**骨架范围**：**只有真实账号的卡用骨架**。
「添加账号」是**真实按钮**、加载期照常渲染（它本来就始终在），
所以它不占位、也不需要「+1」张的补救 —— 网格里永远有那张真卡。

**卡数**：读到账号后记在本机（[skeleton-hint.ts](../src/client/skeleton-hint.ts)），
下次首屏按它摆卡。骨架出现时缓存必然是空的（有值就不进 `loading`），
所以只有**跨页面加载**的记忆帮得上忙；读不到 / 写不进 / 脏值一律回退兜底常量。
