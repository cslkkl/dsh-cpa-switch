## 1. 面板在哪

- **插件页**：DSH 的 **插件 → CPA 切换器**。这是**一直都在**的入口。
- **左侧栏那一行**：面板最底部有一个「侧栏入口」开关，**默认关**。打开后入口出现在
  左侧栏那一列插件图标里（与「插件 / 自动任务 / 用量统计 / SSH」并列）；
  关掉之后那一行**整条不在**，面板只从插件页进。

侧栏是宿主与所有插件共用的一列，所以默认不占位 —— 要不要占由你按那个开关决定。
**想把它收起来**就直接点那一行右侧的「取消固定」（宿主画的按钮）：那是宿主的
收纳能力，刷新后仍然生效（它是宿主的内存态，插件重启会回到默认的「显示」）。

## 2. 配置字段

| 字段                  | 默认            | 说明                                     |
| --------------------- | --------------- | ---------------------------------------- |
| `adminKey`            | 空              | CPA 管理密钥；留空则用凭据库里的引用     |
| `adminKeyRef`         | `CPA_ADMIN_KEY` | 凭据库里的引用名                         |
| `port`                | `8317`          | CPA 监听端口                             |
| `exePath`             | 空              | CPA 可执行文件路径；留空自动探测         |
| `manageLifecycle`     | `true`          | 是否由插件负责 CPA 的启动和停止          |
| `autoCheckinOnStart`  | `true`          | 启动时补一次漏掉的签到                   |
| `openControlPanel`    | `false`         | CPA 启动时是否同时打开它自带的网页控制台 |
| `reasoningEfforts`    | `true`          | 是否让模型可切思考档位（关 / 开两档）    |
| `maxOutputTokens`     | `384000`        | 推给宿主的每模型输出上限；`0` = 不声明   |
| `startTimeoutSeconds` | `30`            | 等待 CPA 就绪的最长秒数                  |

⚠️ **输出上限**：插件把 `maxOutputTokens` 推给宿主的每个模型（宿主字段 `maxTokens`），
让请求不再被 DSH 兜底的 32768 提前截断。实测它**目前只在 WorkBuddy 渠道真正生效** ——
qoder 由服务端模板自带上限、客户端值不进请求，trae 会丢弃该字段并自行补大值；给这两家
声明是为渠道侧支持后自动生效。默认值 384000（DeepSeek V4 系列的输出上限天花板）是
**报大**方向：上游对超报值不拒绝（实测 384000 发给真实上限 128k 的模型也正常返回），
截断职责仍在上游。链路与实测见
[实测报告](audits/2026-10-08-cpa-stream-probe.md) 的附录。

## 3. 四个渠道差在哪

| 渠道      | 账号数 | 余额单位  | 签到 | 任务 |
| --------- | ------ | --------- | ---- | ---- |
| WorkBuddy | 多号   | 积分      | ✅   | ✅   |
| Trae      | 多号   | 积分      | ✅   | —    |
| Qoder     | 单号   | 积分      | ✅   | —    |
| ZCode     | 单号   | **token** | —    | —    |

四个渠道上报的余额字段**不是一套**：Trae 只有一个余额池，上游不给总额与已用，
所以它那格显示 `—`、也不画进度条 —— 那是「上游没说」，不是「用了 0」。
token 与积分分开显示，不混加；额度数字到百万级自动缩写（`508M tokens`，只上一档 `M`，
不改写成 B）。

**按能力降级**：渠道不支持的功能不显示，不给「点了没反应」的按钮。

## 4. 对话里的模型

装完插件、加完账号，四个渠道的模型会自动出现在 DSH 的模型选择器里：

- 模型按**渠道分组**显示：分组标题就是渠道（如 `CPA Switch · WorkBuddy`），
  组内每一行是**模型名本身**（如 `deepseek-v4.1-flash`）—— 一眼看出请求会走谁。
  这个 provider 在 DSH 里显示为 **CPA Switch**。
- 同一个模型被多个渠道供给时，每个渠道各出一条 —— **选了哪个渠道，就只用那个渠道的号**，
  不会跨渠道轮询消耗你的其它号。
- **只列能用的**：已被禁用、已报错或当前不可用的账号，它的模型不会出现 ——
  选择器里不会有「点了才发现调不通」的条目。
- **只列这四个渠道**：CPA 上可能还装着本插件不管理的渠道，它们的模型**不出现**；
  插件不认的渠道不会有管理入口，与其给你一个选不上的名字，不如不列。
- **启动时不会先给一份残缺的清单**：重启 DSH 后如果第一次读到的目录还不完整
  （CPA 刚起、账号还在分批加载），插件会继续用上一次的完整清单，并在几秒内自动重读补齐 ——
  不会出现「只剩一两条模型」或「只剩一个渠道」的中间态。
- **只让常用的进选择器**：面板工具栏上有个「模型」按钮，点开取消勾选某个模型并保存，
  它就从对话界面的下拉里消失（**面板里照旧列出全部**，随时可以勾回来）；
  不勾只是不在下拉里，模型本身照常能调通。

加了新账号、删了账号，模型清单自动跟着变。机制与设计见[架构说明](ARCHITECTURE.md)。

### 4.1 思考档位

模型选择器里每个模型可以切**思考档位** —— 两个选项：

- **关**：不让模型输出思考过程，直接给答案
- **开**（默认）：模型先想再答，思考过程在对话里**看得见**

默认**打开**（`reasoningEfforts: true`）。想整体关掉就去插件设置里关这个开关 ——
关掉后 Effort 那一行会消失，回到不带档位的老行为。

⚠️ **只给两档是有意的，不是没做完。** 实测上游对「低 / 中 / 高 / 最大」这类中间刻度
**不按刻度办事**（同一档位内的波动比档位之间的差还大），给了就是在制造错误预期。
所以只暴露两个语义确定的值：**关**与**开**。理由与实测数据见
[决策记录](../.agents/notes/2026-10-06-reasoning-effort-two-levels.md)。

⚠️ **「关」发出去的那个词按渠道自动适配**（zcode 只认 `none`、不认 `off`），
所以四个渠道上选「关」都不会因为用词被上游拒。

⚠️ 如果上游某个时刻拒绝档位值（整轮对话报错），**把上面那个开关关掉**即可恢复。

> **菜单里为什么有一行 `Default`**：它是 DSH 在「路由没声明默认档位」时补的，
> 语义就是**什么都不发、由上游自己决定**。档位这事各模型差别很大、上游还常改，
> 所以插件不钉默认值 —— `Default` 就是那个兜底，另外两行是插件给的两档。
> 曾经钉过（`high`）以去掉这一行，但那会把**摘掉档位的模型**整轮打崩，已撤。
> 原理与取舍见[决策记录](../.agents/notes/2026-10-06-reasoning-default-row-removed.md)。

## 5. 账号与「你的选择」

- **一键签到 / 一键任务**：整个渠道一次点完；每个账号也可以单独操作。渠道不支持的那个
  按钮不会出现。
- **启用 / 禁用账号**：每个账号一个开关；「只用这一个」一步把同渠道其余账号全部禁用。
- **添加账号**：每个渠道列表末尾的「+ 添加账号」，在浏览器里完成 OAuth 登录即可。
- **记住你的选择**：重启 DSH 后，在用的仍是你上次选的号；运行期间被别处改回去
  （渠道插件会按额度自动重新启用账号）时，面板会照你的选择恢复并提示一句 ——
  期间开关不会反复跳回「全开」再弹回来。
- **自动签到**：按渠道开关；DSH 没开而漏掉的签到，插件启动时补一次。
- **进程托管**：DSH 开则 CPA 起（已在跑就复用），DSH 关则一并停止（`manageLifecycle`）。

## 6. 起不来的时候看什么

端口被别的 CPA 占用、配置代际不符、配置加载失败是**三种不同的原因**，面板各自点明，
处置也不同；端口被外部实例占着时不会假装「运行中」。

- 代际不符 / 配置加载失败：删掉托管目录里的 `config.yaml`，再点「一键准备环境」，
  插件会重新生成一份。
- 端口被占：先停掉那个外部实例，或把 `exePath` 指过去并填上它的管理密钥（面板会说明
  插件停不掉它、也用不上它的密钥）。

原因判定的实现与「认不出就不报原因」的口径见[架构说明](ARCHITECTURE.md)的防错清单（F46）。

## 7. 渠道插件版本

**渠道插件不会被自动升级**（上游随时可能改行为，静默替换风险太大）。
面板上会显示「渠道插件 a → b」，需要时点一次「更新渠道插件」：
它会先停 CPA、保留一份旧件、失败自动还原，换完不自动重启。

## 8. 已知限制

- **仅 Windows**：CPA 目前以 Windows 可执行文件 + DLL 插件形式提供。
- **下载要能访问 GitHub Release**：直连不通时需要代理。
- **被限流的号界面看不出**：面板显示「启用」不代表「现在能用」，只有实际对话报错才发现
  —— 详见[架构说明](ARCHITECTURE.md)的防错清单（F14）。
