## 新功能

- **老机器的托管配置会自动补上 `server.host: "127.0.0.1"`**。缺这一行时 CPA 监听所有
  网卡，同一局域网里的人**不带任何鉴权**就能调 `/v1/*`，直接消耗你的账号额度
  （2026-10-04 实测 `http://<内网 IP>:8317/v1/models` 返回 200）。
  生成的逻辑只在「配置文件不存在」时写，所以**已经跑过一次的机器一直暴露着** ——
  升级插件也救不了。现在每次 DSH 启动、CPA 未运行时检查一次，缺就补。
- **只补「缺失」，不动你的选择**：配置里已有 `host`（哪怕写的是 `0.0.0.0`）是知情决定，
  一律不动；没有 `server:` 段的配置看不懂，放弃且不改文件。
- ⚠️ 这条改的是**宿主半端**，装完要**重启 DSH**（刷新页面不算）。补写只在 CPA
  未运行时做 —— 它运行中持有该文件、保存时会回写，那时改是抢写。

## 修复

- **`hunyuan-chat` 的思考档位开关撤掉了**。实测它 `off` 与 `high` 两档**都完全不思考**
  （三条 token 路径全是 0），开关给出去无论选什么都得到同一个结果 —— 是个假旋钮。
  现在该模型不再出现 Effort 行，其余模型照常。

## 内部改动

- 思考档位的**逐模型省略**机制：校准表加一个「省略声明」标记，只认实测反证
  （真·假 high）的模型，方向与「支持图像」的标记相反、且没有 `true` 这个值。
  同一渠道里其它模型不受影响，路由级默认档位也不动。

## 升级

```
dsh plugin --profile <profile> add dsh-cpa-switch
```

装完**重启 DSH**：本批改的是宿主半端。无配置变更、无破坏性改动。

## 复验

- 重启 DSH、CPA 未运行时，看终端有没有那行
  `托管配置缺 server.host，已补 "127.0.0.1"`；已在托管配置里写过 `host` 的机器
  **不应**出现它（判据是「一字节不动」）。
- 模型选择器里 `hunyuan-chat`（WorkBuddy 渠道）**不应**再有 Effort 行，
  同渠道其它模型照常有。

## 版本号说明

取 **minor**：两个新增能力 —— ① 老机器的配置自动补安全默认值（使用者能观察到
`host` 从缺到有、局域网暴露面消失）；② 一个假开关被摘掉（选择器里少一行 Effort）。
按[发布手册](https://github.com/cslkkl/dsh-cpa-switch/blob/main/docs/PUBLISHING.md)
的口径，新增能力 / 行为变化走 minor。

⚠️ 本批有**事故记录在内**：`server.host` 自动补齐的首版写死了缩进，把已被 CPA 回写过
（4 空格缩进）的托管配置变成了非法 YAML，导致 CPA 静默起不来。修复已随本版发出，
判据（含「真机 4 空格形态」用例）见复盘。
