## 修复

- **重启后模型选择器不再只显示 1 个模型（或只剩一个渠道）**。第 1 批真机三次重启里
  **中两次**：选择器里只剩 `WorkBuddy · deepseek-v4.1-flash` 一条，或只剩一个渠道的
  模型，几秒后 / 点一下才自愈。
  根因是**启动时读到残缺目录、被当完整写进了磁盘缓存** —— 那份缓存每次启动会先推回
  选择器，于是残缺可能变成**永久**的。
- 写盘判据从「**非空吗**」换成「**比上一份差吗**」：CPA 的模型目录只会因加号增长
  （加号、加渠道、重启加载），不会自己缩小。少了模型的那一份**不写盘、不推送**，
  继续用上一份。
- 补上**有限重读**：读到残缺时按 `2 / 5 / 15 / 30` 秒再读几次，**四次封顶**。

## 机制

- **重读只由迹象触发、不由时间触发**：没有「这一份比上一份差」就不多读一次；
  且只在会改 CPA 模型注册表的时机排（`boot` / `setup` / `oauth`）——
  切语言那类 `config-reload` **不排**，否则就是无脑轮询。
- **删号 / 禁用账号仍然立刻反映**：缩水分两种 ——「读残了」（拦下）与「合法地少了」
  （某个渠道被跳过、或它的凭据被禁用 / 报错）。后者按**渠道**放行，
  且**只放行那个渠道**：整体放行的话，用户只要有一个长期禁用的号，
  这道护栏就永久失效。
- **不会永久卡死**：四次重读都没读到更好的，就**放行**最后一次读到的清单。
  否则一次真的缩水（删了号、而这次没留下任何信号）会让**已经删掉的模型**
  一直留在选择器里 —— 比少显示更糟。

## 升级

```
dsh plugin --profile <profile> add dsh-cpa-switch
```

装完**重启 DSH**：本批改的是宿主半端的模型路由，不随页面刷新加载。
无配置变更、无破坏性改动；**不需要清缓存**（旧的缓存文件照常可用）。

## 复验

重启 DSH 三次，看选择器：

- 三次都**不应**出现「只剩 1 条模型」或「只剩一个渠道」的中间态；
- 若出现，应在 **2 秒内**自愈（终端会打一行 `排有限重读`，随后
  `model routes …:retry`）；
- 反向也要看一眼：**在面板上禁用一个账号**后，它名下的模型应**立刻**从选择器消失
  （逃生口生效，没被护栏卡住）。
