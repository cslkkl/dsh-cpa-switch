## 新增

- **模型选择器里多了一行「思考档位」**：关（Off）与开（High）两档，面板上还有一个总开关
  能整体关掉。从前 CPA 的模型**连选的地方都没有** —— 上游其实支持，缺的只是「声明」这一环。
- **档位默认是「开」**，也就是升级后行为不变；不想要的话把总开关关掉，就回到从前
  「不带档位」的样子。

## 修复

- **状态条与两条告警一直不显示**：`/status` 的响应体少了一个 `ok: true`，
  浏览器侧据它判成败，于是整块数据恒为空 —— 而宿主这边 HTTP 200、逻辑也对，
  **控制台和日志都看不出问题**。这是本仓记过的坑，这次栽在 `/status` 自己身上。
- **选择器里那个多余的 `Default` 行没了**：它不来自本插件，是宿主在「路由没声明默认档位」
  时补的一行。现在把默认档位声明成 `High`，那行就不再出现，只留 `Off` 与 `High`。

## 为什么只有两档

实测（`wb/deepseek-v4.1-flash`，每个档位各 10 次）：**「关」是硬的** —— 恒为 0 个思考 token，
20 次无例外；而 `low` / `high` / `max` 之间**测不出显著差别**（t 值 0.35 / 1.39 / 1.64，
一般要 ≥2），**同一档位内部的波动（±280）比档位之间的差（±200）还大**。

既然测不出差别，就不给用户一个假旋钮 —— 选 `max` 未必比 `high` 想得多。

## 已知边界

- **「关」不是所有模型都真能关掉。** 关于这一点的**完整实测结果**单独成文：
  [思考档位实测](https://github.com/cslkkl/dsh-cpa-switch/blob/main/docs/audits/2026-10-06-reasoning-effort-off-vs-high.md)
  —— 99 个模型逐个对照 `off` 与 `high`，只有 10 个是真开关，23 个甚至**方向相反**
  （选「高」反而想得更少）。**本次不修**，先把实测事实记下来。
- ⚠️ **个别渠道会对档位返硬错误、让整轮对话失败**（如 `zcode` 的合法词汇里没有 `off`）。
  这就是那个总开关的**首要价值**：抽风时关掉它，即回到「不声明档位」的老样子。

## 升级

```
dsh plugin --profile <profile> add dsh-cpa-switch
```

装完**重启 DSH** 生效。无配置变更、无破坏性改动；档位默认开启，升级后行为与从前一致。
