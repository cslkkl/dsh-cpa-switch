# v0.22.0

## 新增：新模型体检，把「看图能力」也纳入

以前只管上下文窗口；现在**检测到新模型，先查两样：① 上下文窗口 ② 有没有看图能力**。

少查任何一样，用户都不会收到报错，只会得到一个假数字或一个假能力：

| 少做了什么   | 用户看到什么                                           |
| ------------ | ------------------------------------------------------ |
| 没登记窗口   | 上下文显示 262K（宿主兜底），压缩早早触发              |
| **没标看图** | 附加图片时**在发出前就被拒**，还以为这个模型本来就不行 |

第一次跑体检就抓出 **4 条漏标**，它们一直让「加图片」这件事看起来不存在：

`deepseek-v4-pro`、`kimi-k2.8-preview`、`kimi-k3-1`、`step-5-preview`（WorkBuddy 侧）。
这些现在都能带图了。

## 新增一条判据：`imagesMissing`

- **只在渠道侧明确说支持时才算漏** —— 「没标」也可能是「查过、确实不支持」，
  不区分就会逼着人把确认不支持的也标上，代价是会话卡死；
- **反方向不管**：表里标了、渠道没报，以表为准。本仓就有「官方文档说纯文本、
  实测证明带真视觉」的先例（`glm-5.3`），自动改回去比漏标更危险；
- **运行时故意不自动补这一条**：图像标错是**不可逆**的（图片已发出、消息已落库、
  provider 中途拒绝 ⇒ 会话卡在反复重试）。窗口可以自动补，看图能力必须人过一眼。
