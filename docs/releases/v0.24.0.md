# v0.24.0

## 变更（行为变化）

- **第五个上游整条下线，回到四个渠道。**

  上一版接进来的那个 OpenAI 兼容上游，这一版把整条接入面**移除**：渠道注册表回到四个、
  生成的配置不再为它写任何段、面板不再有那个登录入口、宿主骨架不再有第五个 provider。

  使用者能看到的变化：

  - 模型选择器里**不再有**第五个分组；已有的选择会失效，重选一次即可。
  - 插件设置里那三个字段（上游地址 / 凭据引用 / 模型清单）**消失了** ——
    它们只服务这条接入面。
  - `cordis.patch.yml` 的 provider 骨架从五行回到四行；已装机器重启后宿主侧只注册四组。
  - 托管 `config.yaml` 里**不会再为它写任何段**；旧机器上残留的那一段不会被插件删除
    （那是用户自己的配置，插件只停止维护它）。

  内部一并撤掉的还有：按「管理面由谁提供」分叉的那一维、依赖它的账号 / 模型读取钩子、
  以及只服务它的测试与脚本。

## 修复

- 无（本次只做移除；上一版的档案类修复保留）。

## 重构与内部改动

- 渠道骨架回到单一形状：四个渠道都是「管理面是 CPA 渠道插件」，
  同构路径恢复成注册表里的模板，渠道 spec 不再有可选覆盖。
- 登录入口判据只剩两位：`cpa`（CPA 的 OAuth）与 `none`（不给入口）。
- 状态文件少了一个：那次登录产物只服务被移除的接入面。
- 思考档位的「整条不发」名单随之清空 —— 它唯一那条是为那个上游加的。

## 升级

```
dsh plugin --profile <profile> add dsh-cpa-switch
```

装完**重启 DSH**（宿主半端有改动：路由骨架、装配、配置生成），浏览器半端刷新页面即可。
**无配置迁移**：账号意图、显示偏好、模型可见性文件都不动；只有上一版新增的那三个设置项
会随渠道一起消失。曾接过那个上游的机器，如果想让 `config.yaml` 干净，
手动删掉那一整段即可（插件不再读写它）。
