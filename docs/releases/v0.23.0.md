# v0.23.0

## 新功能

- **豆包工作能接成第五个上游了 —— 默认不接。**

  它不是 CPA 渠道插件（那个仓库是独立的 Node 网关，零 Go、零 dll），所以走 CPA 配置里的
  `openai-compatibility`：由 CPA 把它当上游代理，本插件只负责把它算成一个渠道、让它的模型进选择器。

  - 三样齐全才写这段配置：地址、密钥（凭据引用）、**模型清单**。三样任一为空都不接 ——
    但三种「空」在日志里分开说，「没打算接」与「想接但没配好」不该长得一样。
  - **模型清单必须自己填**：CPA 不会去探测上游的 `/v1/models`，写空就是一个模型都不出现。
    填裸名，前缀由插件加（`dbw/` 那一层不许自己写，写了两层会叠成 `dbw/dbw/…`）。
  - **它只支持纯文本对话**：那个网关明确拒收 `tools` / `function_call` / `response_format`。
    所以模型能选中、能聊，**工具调用会直接 400** —— 这一侧无解，只能等上游实现。
  - **思考档位整条不发**：这条上游不认 `off`（它最低的一档是 `low`），发过去是每一轮 400。
    所以它的模型**不声明**任何档位：界面不出现 Effort 行、请求也不带档位参数。
    其余四个渠道照旧「关 / 开」两档，值仍按渠道给（zcode 的「关」是 `none`）。
  - **「+ 添加账号」真的能点**：走那个网关自己的独立浏览器登录，登完自动把密钥与模型清单带回来。
    网关没装 / 装了起不来 / 探活不通 **三句话分开说** —— 它们对应三种完全不同的下一步，
    合成一句只会让人反复点同一个按钮。
  - 账号与模型两个读取各走渠道 spec 的钩子：compat 的凭据**不进** `auth-files`，
    套渠道插件那套模板端点只会得到 404，而 404 在界面上与「这个渠道没有账号」完全同形。

- **侧栏入口回到左侧栏那一列图标里（默认仍然关）。**

  上一版把入口收进了侧栏的「更多」菜单 —— 那个方向是反的：打开开关时**栏上什么都不变**，
  用户要验证它生效还得再点一次去翻菜单，而那一行恰恰是他按开关时唯一期待看到变化的地方。

  - **开关开着的：栏上多一行**，点了直接进面板；关掉就整条不在，面板只从插件页进。
  - **从上一版升级上来、开关本来开着的**：刷新后入口会从「更多」搬回左侧栏那一列，不用重新开一次。
  - 想收起来的人用宿主自己的「取消固定」—— 那是宿主的内存态，插件不替用户拨。
  - 旧宿主那段「等 2 秒没见『更多』就退回栏上」的兜底删掉了：栏上这个座位在本仓声明的
    最低宿主上一定存在，留着只会让下一个读代码的人以为它可能不存在。

## 修复

- **禁用的号不会再被上游悄悄启用。**

  症状：只启用一个号，过一阵打开面板弹「恢复你禁用的 N 个账号」，号全亮了。现在**这个「恢复」
  不再需要发生** —— 渠道插件自带的额度生命周期（09:00 / 21:00 之后把「被禁用但额度未耗尽」的号
  写回启用，分不清那个禁用是谁点的）在启动时被关掉，于是这个开关只剩两个写者：你，和本插件。

  - 关它是幂等的、回读确认，且**不需要重启 CPA**；trae 没有这个字段，直接跳过。
  - 万一还是出现了（老配置、别的机器、你自己又开回去）：宿主侧守卫每 5 分钟按你的选择改回来，
    面板打开时另有一句提示。
  - **代价（明确接受）**：额度耗尽的号不再被自动禁用，改由 CPA 自己的 cooldown 兜底 ——
    失败 → 冷却 → 换号。换来的是「你的禁用不会被任何人撤销」，这条以前只是「我们修得比较快」。

- **对话输入栏那个积分读数不再显示整个渠道的总和，也不再停在旧数上。**

  两个缺陷叠在一起：读数只按「后端写着启用」求和（不知道你的意图），而它偏偏是常挂的、
  只在挂载那一刻读一次，于是面板修完漂移、返回对话又「正常」了 —— 那只是座位重挂了。
  现在漂移号按**禁用**算（与面板开关同一条口径），两侧取值**按时间取新**，别处读到的新值立刻看得见。

- **上游仓库消失时，渠道插件更新回退到本地离线归档。**

  上游那个账号被封、仓库 404 之后，面板只能给「重试」，而唯一已知的镜像只有源码 tag ——
  把下载源换过去会更糟：解压「成功」，落进 `plugins/` 的却是 `.go` 源码。

  - 网络侧所有源都失败时，改用本地最后一份已验证产物重装**同版本**；界面**明说「不是新版」**，
    升级完成的提示也这么说 —— 把它报成一次普通更新，就是让人以为上游还活着。
  - 归档「读不懂就当没有」：清单缺字段、文件不在、声明大小与磁盘不符、清单点的不是这个来源的包，
    一律不认。
  - 离线那条**照样算 sha256**：「先校验再解压」这条不变量不为离线让路。

- **清单里新增的两个渠道能力位：不发档位的渠道不再硬凑两档。**

  原来「关 / 开」是所有渠道一起发的，只有「关」用哪个词能按渠道换。豆包工作接进来之后这条
  不成立了 —— 它的词汇表里根本没有「关」。现在多一个「整条不发」的档位：不发就是不发，
  不发不等于发空串（后者会连累整个 provider 注册失败）。

## 重构与内部改动

渠道骨架多了一个维度「管理面由谁提供」（渠道插件 / `openai-compatibility`），省略即老行为 ——
四个老渠道一个字没改；新增宿主侧常驻的漂移守卫；compat 上游的配置解析收成一处，全新安装与
启动补齐共用同一份结果（各拼一遍就会「新装能连、升级上来连不上」）；收 `disabled` 所有权与
漂移守卫都只遍历**插件渠道**（compat 渠道没有账号池，问它只是白打一次接口）。

开发依赖升到当前可用的次 / 补丁版：`@deepseek-ai/cordis` 对齐宿主实带的 4.1.0（devDep 比宿主旧，
本地类型检查看到的就是宿主已经不用了的那一版）；major 的 typescript / vitest / tsdown 刻意不动，
属单独一轮现代化。

## 升级

```
dsh plugin --profile <profile> add dsh-cpa-switch
```

装完**重启 DSH** —— 这次宿主半端有改动（收 `disabled` 所有权、漂移守卫、路由装配、离线回退），
浏览器半端刷新页面即可。**无配置迁移**：账号意图、偏好、模型可见性文件都不动；豆包工作那三个
设置项默认空，等于不接。接了豆包工作的机器，改完那条上游的配置要**重启一次 CPA**（配置不热加载）。
