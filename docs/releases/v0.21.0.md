# v0.21.0

## 修复：三个模型一直显示「262K 上下文」

`kimi-k3.1-pro`、`minimax-m3.1-flash`、`mimo-v2.6-pro` 在渠道目录里一直有，
校准表里却没有它们，于是推送时不写窗口值，宿主落到自己的兜底
**262144** —— 界面上看起来就是「这模型只有 262K」，而渠道目录里写的是 **1M**。

这件事**全程没有任何报错**：跟「它真的只有 262K」长得一模一样。
`kimi-k3.1-pro` 尤其是被这个坑藏住的 —— 它和表里的 `kimi-k3-1`
（渠道里叫 `Kimi-K3`）是**两条不同的模型**，名字太像，一直没人发现漏了。

升级后重启 DSH，这三个模型的上下文条会回到正确读数。

## 新增：新模型的窗口自动补，不必等发版

校准表是编译进产物的，模型却随渠道上游随时变 —— 靠发版追永远慢一步。
现在每次**读全**渠道目录之后会顺手体检一遍：

- 表里没有、**渠道侧给出了窗口** → 自动记下来，下一次推送就用上；
- 表里没有、渠道侧也没有出处 → **什么都不写**，继续走兜底（那是明确的兜底，
  比编一个数字好）；
- 表里**已有**条目 → 一律不动。表是人写的有出处值，运行时数据不许覆盖它 ——
  哪怕那条是「故意不填窗口」，也不许被一次上游读数改掉。

所以「更新渠道插件 → 重启 CPA」这一步之后，新模型的窗口就已经是对的。

## 新增：模型能力维护手册

新增 [docs/MODEL-CAPS.md](../docs/MODEL-CAPS.md)：新模型出现时**两样都要查** ——
① 上下文窗口 ② 思考档位。少查一样，用户得到的就是一个假数字或一个假旋钮，
而两者都不报错。手册里有分渠道的出处可信度表、筛查命令与判读口径
（思考档位必须至少三次重复实测，单次会翻类）。

配套 `node scripts/audit-model-caps.mjs`：一条命令列出「渠道目录里有、表里没有」的模型，
并给出可直接粘贴的补丁行。它**不发模型请求、不烧额度**。

## 说明

- Trae 与 Qoder 的渠道接口只返回模型 id 与显示名，**不返回窗口** —— 所以这两个渠道
  里未登记的模型只报告、不自动补。那是渠道侧证据不足，等上游补字段。
- 自动补的只是**窗口**；思考档位一直只能人工实测（要发真实请求比两档的思考量）。
