## 修复

- **模型选择器里不再出现「有名字、用不了」的条目**。两类症状合并修掉：
  - 冒出 `Kimi · kimi-k2.8` / `MiMo · mimo-pro` —— 实测一个 `status=error` +
    `unavailable=true` 的凭据**照样报出 10 个模型**，而我们只读了模型名、
    没读同一个 `auth-files` 返回里的健康度字段，于是它们被当成健康模型推进清单。
  - `CPA · kimi-k2.7-code` —— 认不出归属就兜底成「CPA 自有」，那是**谎称**：
    CPA 是代理层、不生产模型。
- 模型清单收成 `(CPA 目录) ∩ (托管渠道**可用**凭据供给面的并集)`：
  - **未托管渠道的模型不再出现**（判据是「有没有 spec」，不靠特判渠道名 ——
    CPA 以后新增渠道不需要改插件代码）；
  - **已禁用 / 已报错 / 当前不可用的账号，它的模型不再出现**；
  - **认不出归属就不产出**，不再编一个兜底名。

## 机制

- 渠道注册表的模型 id 前缀表收窄成**只有托管渠道** —— 这是第二道结构性保证：
  即便数据漏进来也挂不上标签。
- 认不出的健康度字段一律当**可用**（「过滤过头」比多列几个调不通的模型严重）。

## 升级

```
dsh plugin --profile <profile> add dsh-cpa-switch
```

装完**重启 DSH**：本批改的是宿主半端的模型路由，不随页面刷新加载。
无配置变更、无破坏性改动。

⚠️ **如果你在 CPA 上装了本插件不管理的渠道**（如 Kimi / MiMo），它们此前出现在
模型选择器里、但调用失败；本批起不再出现。这是预期行为 —— 它们没有面板入口，
插件无法管理它们的账号。

- 决策记录：[模型路由只收托管渠道的可用凭据](https://github.com/cslkkl/dsh-cpa-switch/blob/main/.agents/notes/2026-10-07-model-routes-managed-healthy-only.md)
