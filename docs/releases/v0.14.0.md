## 新功能

- **模型选择器按渠道分组了 —— 不再是一层平铺的近百个模型。**
  选择器是按 provider 分组的，而四个渠道（WorkBuddy / Trae / Qoder / ZCode）的模型
  此前**全挂在同一个分组**下，本机实测 **96 行平铺成一层**，找模型要一直翻。
  现在一个渠道一个分组，组名是 `CPA Switch · <渠道名>`，顺序与面板页签一致。
  - ⚠️ **升级后每个会话要重选一次模型（一次性，之后不再受影响）。**
    选择器的选项身份是 `分组/模型`，分组变了，你之前选中的那个就找不到了。
    打开旧会话时会看到输入框停用，在对应渠道的分组里重选一次即可。
    这是这次分组**必须付的代价**，已确认接受；分组名从此是稳定契约。

- **思考档位按三重复测重做：摘掉 11 个「假旋钮」，对调 4 个「反方向」的。**
  界面上「关 / 开」这一行本来就不总是可信，重测 97 个模型后处置如下：
  - **关不掉的**（选「关」照样思考）与**两档都不思考的** → **摘掉档位列**
    （11 个：`hy4-preview-f`、`step-5-preview`、`Trae` 的 `Doubao-Seed-2.1-Pro/Turbo`、
    `glm-5.2`、`glm-5.3-flash`、`kimi-k2.6`、`step-5-preview`，以及 `zcode` 的
    `glm-5.3` / `glm-5.3-flash`）—— 留着只是给你一个按不动或没意义的按钮；
  - **方向相反的**（选「开」反而想得更少）→ **把两个档位的值对调**
    （4 个：qoder 的 `dfmodel` / `gfmodel` / `gm51model` / `gmodel`），
    让「关 = 想得少、开 = 想得多」恢复正确方向。
    ⚠️ 对调**只修方向**：这些模型「关」那一档仍会思考 —— 上游没给一个真能关掉思考的词；
  - **测不准的 55 个一律不动**：两档的字数区间重叠就判「测不准」。
    上一版是按**单次**测量分类的，而重复测显示**同一批模型有一半翻了类**
    （`wb/glm-5.3` 585/38 → 12/12、`wb/glm-5.1` 真开关 → 测不准）——
    在测不准的数据上改，等于把上一版的错重犯一遍。

## 修复

- **「未签到」标签改成灰底** —— 原来是空心描边，看起来像括号，与绿底「已签到」
  并排时会被读成标点而不是状态。「今天没签」可能是有意不签，所以用中性的灰
  （不是警告色，也不是失败色）。
- 没有签到状态的渠道（Qoder / ZCode）**整行不显示**任何标签 —— 那是「不知道」，
  不是「没签」，此前就是这个行为，本版把它写成了正式判据。

## 内部改动

- 模型 id 的解析收成一处：渠道那侧不再抄一份目录的解析逻辑。
- 模型窗口校准表：**窗口允许缺省** —— 档位标记与窗口是两条独立的证据轴，
  Trae 平台模型的窗口按渠道口径仍不填（走宿主兜底），不再为了挂档位标记
  去凭空补一个窗口值。

## 升级

```
dsh plugin --profile <profile> add dsh-cpa-switch
```

装完**重启 DSH**（改的是宿主半端）。无配置迁移；唯一的破坏性影响是上面那条
**一次性重选模型**。

## 复验

- **分组**：模型选择器里应出现四个分组（`CPA Switch · WorkBuddy / Trae / Qoder / ZCode`），
  不再是单个分组下近百行。
- **重选**：旧会话打开时输入框停用 → 在对应渠道分组里重选一次模型 → 恢复可用。
- **档位**：`workbuddy/step-5-preview`、`zcode/glm-5.3` 这类模型**不应有 Effort 行**，
  同渠道其它模型照旧；`qoder/gmodel` 选「开」应比选「关」想得更多。
- **标签**：没签到的号上是一个**灰底**「未签到」标签，不再是空心描边。

## 版本号说明

取 **minor**：两处使用者可观察到的变化（选择器分组、档位摘除/对调）加一处修缺陷
（未签到标签）。按[发布手册](https://github.com/cslkkl/dsh-cpa-switch/blob/main/docs/PUBLISHING.md)
的口径，行为变化走 minor。

⚠️ **本版有一处破坏性影响**：模型选择器**改分组**，你之前保存的模型选择会失效一次，
需要在新的四个分组里各重选一次（旧的 `cpa` 分组会被清掉，不会留下幽灵分组）。
