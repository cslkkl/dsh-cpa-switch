## 修复

- **开机第一条消息不再报 `UNKNOWN_MODEL`**。现象是 dsh web 起来后发第一条消息必报
  `pi-ai provider "cpa" has no configured model "wb/…"`，重开一次 dsh web 才好。
  两个成因落在同一个窗口：选择器读的是 `providers.cpa` 的骨架，而骨架里没有模型清单
  （清单只能运行时推），推清单原来又挂在「CPA 就绪」上 —— `ensure()` 的预算
  （默认 30 秒）用尽时只 warn 一句，既不重试也没有兜底，磁盘上那份完整清单白躺着，
  只能等某次写设置撞上配置重载。
- 现在**装配那一刻**就读磁盘缓存推一次，`boot` 再无条件推一次并记下结果；
  序号护栏判在「等到条目之后」，免得装配即推醒来时盖掉后来推上去的新清单。
  ⚠️ 这条改的是**宿主半端**，装完要**重启 DSH**，刷新页面不算。

- **切渠道不再丢「在飞」和结果，也不会因此重复签到**。在 A 渠道点「全部签到」，
  立刻切到 B 再切回来：提示没了、按钮也不「忙」了 —— 于是可以再点一次，重复签到。
  反过来更糟：A 的结果在切走之后才回来，会被当成 B 的结果显示
  （文案说「签到 4 个账号」，而用户正看着 B）。两个症状同一个根因，且都不报错。
- 现在四个动作状态按**发起它的渠道**分槽记：在 A 发起的动作只让 A 显示在飞，
  切到 B 再切回 A 状态还在；结果只回到发起它的那一格。

## 新功能

- **额度包周期提醒**：上游明确给出结束日期的额度包，在周期结束前 **7 天**内，
  面板上会出现一条可展开的提醒，展开可见**账号 / 包名 / 余量 / 结束时间**。
  - ⚠️ **周期结束不等于未用额度一定失效** —— 提醒里那行小字就是这么写的，
    别把它当成「额度要过期了」的断言。
  - 只认两类日期：明确的日历日期、带时区的时刻。余量已经是 0 的包不报；
    日期不可解析、或已经过期 / 超出 7 天窗口的也都不报。

- **空渠道说明「这个渠道还没有账号」**：0 个账号的渠道原来只有一个虚线加号座，
  看着像坏了 —— 虚线只说明「这是个入口」，不说明「这里本该有东西、现在一个都没有」。
  现在补一句说明加一句引导，引导里的按钮名跟着界面语言走。
  - **读失败和加载中都不显示这句**：读不到时条数必然是 0，先说「没有账号」
    会让人去重加一个已经存在的号。

## 升级

```
dsh plugin --profile <profile> add dsh-cpa-switch
```

装完**重启 DSH** —— 本批含宿主半端的模型路由改动，不随页面刷新加载。
无配置变更、无破坏性改动；**不需要清缓存**（旧的缓存文件照常可用）。

## 复验

重启 DSH，**在发第一条消息之前**看终端：

- 应出现 `装配即推缓存清单` 与 `model routes at boot`，且选择器里已有模型；
  第一条消息不再报 `UNKNOWN_MODEL`。

面板上（浏览器半端，刷新页面即可）：

- workbuddy 点「全部签到」立刻切到 trae —— trae 上**不应**出现 workbuddy 的提示，
  也不应跟着变「忙」；切回 workbuddy 能看到提示，在飞期间按钮一直禁用。
- 看一个 0 账号的渠道：应出现「这个渠道还没有账号」；把 CPA 停掉让读取失败时，
  这一句**不出现**。
- 有额度包在 7 天内到期的账号：应出现可展开的提醒，展开后四列齐全。
