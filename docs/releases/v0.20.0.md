## 新功能

- **「设为唯一」不再「一启用就消失」。**
  以前只要某个号是启用状态，它卡片上就没有这个按钮 —— 于是同渠道开两个以上的号时，
  **已经启用的那几张卡一个入口都没有**，想收敛到其中某一个，只能先把别的号一个个手动关掉。
  现在的规则按**这个渠道里有几个号启用**来定：

  | 启用的号 | 哪些卡上有「设为唯一」                                                 |
  | -------- | ---------------------------------------------------------------------- |
  | **1 个** | 只有**禁用的**那些卡（那个唯一的号没有 —— 它自己已经是「唯一」了）     |
  | **0 个** | 全部（收敛的目标还没定，每张卡都是入口）                               |
  | **多个** | **全部**，包括已启用的那几个（「就它，别的关掉」正是最常用的一次点击） |

  四个渠道通用。

- **token 数量过百万自动缩写。**
  ZCode 这类渠道的额度动辄几亿，整串千分位读不出量级。现在到百万级换一档：
  `508,000,000 tokens` → **`508M tokens`**、`5,080,000,000 tokens` → **`5,080M tokens`**。

  - **只上 `M` 这一档**，不会写成 `5.08B` —— 同屏两个档位反而更难比大小；
  - 一百万以下照旧是千分位（`999,999 tokens`）；`0` 仍然不带单位，缺失仍然是 `—`；
  - 卡片两格、顶部汇总三格、额度包周期余量、对话界面模型选择器左侧的读数**一起生效**
    （四处本来就共用同一个格式化函数，所以「同一屏两种写法」在结构上不会出现）；
  - 百万档保留最多两位小数（`1,234,567` → `1.23M`）：纯取整会把它说成 `1M`，
    少报 23%，缩写的目的是「一眼比大小」而不是把数量级之外的信息也扔掉。

- **侧栏入口收进「更多」菜单，不再占栏上那一行。**
  打开面板底部的「侧栏入口」开关后，入口现在落在**侧栏的「更多」菜单里**（宿主官方给
  低频入口留的折叠位），那一行带本插件的图标，点了直接进面板。

  - **只回答「要不要入口」，不回答「放哪」**：栏上是宿主与所有插件共用的一列，
    插件默认不占；开关关着（默认）时面板只从「插件」页进；
  - **旧宿主有兜底**：「更多」这个位置是宿主 `0.2.1-rc.3` 才声明的，
    更老的宿主上等 2 秒仍没有这个位置就退回栏上那一行 —— 是「看得见的降级」，
    而不是「开关明明开着、侧栏里什么都没有」；
  - 从上一版升级上来、开关本来开着的：入口会自动换到「更多」里，不用重新开一次。

- **换渠道插件时，手放的补丁文件不会再被静默冲掉。**
  渠道插件的「更新」是「清空 `plugins/` 再解压」，此前直接压进 `plugins/` 的手放 dll
  会在下一次更新时**无声消失**。现在托管 CPA 目录下有一个 `overrides/`：

  - 把临时补丁（上游还没修、或修了没发版）放进 `overrides/`，每次更新解压完会自动叠回去；
  - **目录即清单**，里面有什么文件就是当前生效着哪些补丁，不用登记；
  - 退役 = 删掉那里的文件 + 点一次「更新」；
  - 目录本身由启动时预建 —— 与其它「改托管配置」的动作一样，只在 **CPA 未运行**时进行。

## 修复

- **摘了思考档位的模型不再「一开口就整轮报错」。**
  选了这类模型（例如 `zcode/glm-5.3-flash`）发第一条消息就失败，报
  `UNSUPPORTED_REASONING_EFFORT`「model does not support reasoning effort high」——
  而界面上**根本没有 Effort 这一行**、你也没选过 `high`。根因是插件在**路由级**
  声明了一个默认档位，该字段对整条路由的每个模型都生效，而档位能力是**逐模型**的：
  被摘掉档位的模型只认 `off`，请求时拿不到界面值就退回那个默认值，于是每次请求都炸，
  而界面无入口可改。现在档位一律逐模型给。

  - **代价**：档位菜单里多回一行 `Default`。它是对的选择 —— 档位按模型和版本一直在变，
    硬编猜不准，`Default` 本来就是「不发参数、由上游决定」的兜底。

- **删除按钮现在看得出是「危险动作」。**
  以前它是无边框文字，混在「签到 / 任务 / 设为唯一」那排有框的按钮里不像按钮，
  而它恰恰是这一排里唯一不可逆的。

  - 卡片上的「删除」与确认框的「确认删除」都换成**与兄弟逐字相同的黑框 + 红字**
    （红只在文字上，框、宽度、右端对齐、亮暗主题全部跟随兄弟）；
  - 确认框正文一并收短：删的是什么、后果（要重新授权一次）、以及替代方案
    （只想让它不参与调度的话用卡片上的开关禁用即可），三件事一件没少，中英都压到一行内。

- **工具栏顺序改成「全部签到 → 全部任务 → 模型 → 刷新」。**
  刷新从最前挪到最末：前三个是「对号做事」，刷新是**读**、最坏情况只是重看一遍。

- **「模型」弹窗的说明不再是一整段，也不再显示字面星号。**
  标题下那一句只说价值（选择器会变短）；机制那句（**没勾 ≠ 删不掉**，只是不进选择器，
  而且保存后才生效）降成小号辅助文字。中英同步。

## 升级

```
dsh plugin --profile <profile> add dsh-cpa-switch
```

装完**重启 DSH** —— 这次宿主半端有改动（插件更新的解压后回放、启动时的目录预建、
路由装配），浏览器半端刷新页面即可。**无配置迁移**：账号意图、偏好、模型可见性文件都不动。

一个可观察的副作用：托管配置里 `plugins.configs.workbuddy` 会补上一行
`stream_head_timeout: 5`（上游自 0.9.34 起就有的正式字段）。它让流式请求的失败保留
上游 HTTP 状态码，不至于一次请求被风控就把整个账号池轮换 + 冷却一遍。补写只在
**CPA 未运行**时进行 —— 常驻不重启的机器要等下一个停机窗口。已经手写过这个值
（含显式写 `0` 关掉）的配置**一字节不动**。

## 复验

- 同渠道开两个号 → 两张卡上**都有**「设为唯一」；点其中一个 → 它保持启用、另一个被禁用，
  此时**只有被禁用的那张**还有按钮；全部禁用 → 每张卡都有按钮；
- ZCode 的账号额度显示成 `508M token`（中文）/ `508M tokens`（英文），顶部汇总三格同样带 `M`；
  WorkBuddy 那种几千的积分不受影响（仍是 `4,939 积分`）；
- 对话界面模型选择器左侧的读数也带 `M`；
- 面板底部打开「侧栏入口」→ 侧栏「更多」里出现本插件那一行（带图标），点了进面板；
  关掉后消失；两种状态各自跨重启保持；
- 卡片上「删除」是黑框 + 红字、位置仍在按钮行末尾；点它弹的确认框标题带账号名、
  正文两三行说完；
- 工具栏从左到右：**全部签到 / 全部任务 / 模型 / 刷新**；
- 选 `zcode/glm-5.3-flash` 正常对话，档位菜单里有 `Default` 一行；
- 托管 CPA 目录下出现 `overrides/`（空目录也算正常 —— 它就是「补丁往哪放」的提示）；
  往里放一个 dll 再点「更新」，更新完那个文件仍在 `plugins/` 里。

## 版本号说明

取 **minor**：这批同时有使用者可观察到的新能力（「设为唯一」的出现条件、百万档缩写、
侧栏入口的落点、补丁回放）与缺陷修复（档位崩溃、删除按钮的观感）。按
[发布手册](https://github.com/cslkkl/dsh-cpa-switch/blob/main/docs/PUBLISHING.md)
的语义表，档位由**最高阶的那一类**决定 —— 新增能力走 minor。

`0.20.0` 这个版本号**从未发布过**（标签与 npm 都停在 `0.19.0`），所以后合进来的修复
不需要再单独占一个 patch：同一个未发布的版本号可以继续攒改动，重发才是禁区。

正文手写的原因：本文件在第 79 号 PR 时就存在了，而**存在即覆盖**（优先于 Release Drafter
草稿）。规则改变之后又多合进来五个使用者可见的改动，草稿那边是齐的、但它每条只有一行标题。
**补齐本文件**比删掉它更合适 —— 这一版最该让人知道的三件事（选模型一开口就崩、侧栏入口
换了位置、删除按钮换了样子）只用标题带过是读不出来的。
