# v0.21.1

## 修复：`Kimi-K3.1-Pro` 的「思考档位」是个假旋钮

界面上这个模型的「关 / 开」两档，**「关」根本关不掉**。两条独立证据：

- 渠道目录自己写着 `canDisableThinking: false`、`supportedEfforts: [low, high, max]`
  —— `off` **不在合法值里**；
- 实测（同一提示词，看思考正文的字符数）：
  `off` = 200 / 274 / 415，`high` = 358 / 493 / 497 / 540。
  **「关」那一档照样思考 200–415 字**，只是略少。

选「关」的人以为在省 token，其实一样在思考。现在这个模型**不再显示档位行**，
请求里什么都不发，由上游按它自己的默认档（`high`）决定 —— 那才是它的真实行为。

如果你之前觉得它「好像没有思考过程」，选一个不带档位的默认值再试一次。
⚠️ 相邻的 `kimi-k3-1`（渠道里叫 `Kimi-K3`，**另一条模型**）没有同样的证据，不跟着摘。
