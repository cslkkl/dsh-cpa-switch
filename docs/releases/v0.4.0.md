## 新增

- **CPA 起不来时说清为什么**：从前只有一句「未运行」，而三种原因的处置完全不同。
  现在各自点明，并给出现在能做什么。
  - **端口被别的 CPA 占着** —— 机器上早有一份独立 CPA 在跑时，插件起不来自己的实例。
  - **配置代际不符** —— 上游对 `config-version` 是**硬拒绝**（不是降级兼容），
    不符时直接拒绝启动。这一条**在装之前**就在环境准备区说出来，
    不必先撞上「起不来」再猜。
  - **配置本身坏了** —— 配置加载失败的原文透出来，并说明怎么重新生成一份。
- **托管目录多了一份 `startup.log`**：CPA 这一次启动的完整输出。从前它被直接丢弃，
  起不来时手上一份线索都没有。

## 修复

- **端口被别人占着时不再假装「运行中」**：面板此前显示绿色「运行中」，
  而账号列表是空的 —— 用户只能靠猜。现在状态条是**琥珀**点（需注意，不是坏了），
  下面一块提示写清「这个实例不是本插件启动的」以及两条出路。
- **配置代际不符时不再只报超时**：两个版本号都被点出来（「它要 v9、你是 v8」）；
  缺任一数字时退回不提数字的说法 —— **不编**。

## 机制

三条判断共用同一条口径：**宁可不说，也不说错**。

- **子进程输出落文件，不落 pipe**。pipe 必须持续排空，而 CPA 在文件日志关闭时（默认）
  把**每条请求日志**写 stdout —— 排空一停管道写满就**阻塞 CPA 主进程**，
  那是「代理整体挂死」，比丢日志严重得多。
- **端口归属是推断**，不是确证。判据是「在监听 + 不是本进程启的 + 记下的 pid 不在了」；
  Node 反查不了 TCP 监听者的可执行文件路径，做不到更硬的判定。
  关掉 `manageLifecycle` 时**不报** —— 那时端口上有别人的实例是预期内的。
- **代际推不出来**：上游**不存在**「软件版本 → 配置代际」的映射表，
  所以只能读对端自己声明的两侧（它自带的 `config.example.yaml` 与将加载的 `config.yaml`）。
- **认不出失败原因就不报**：辨认靠匹配上游文案，上游改措辞即失效 ——
  那时退回从前的说法，而不是编一个错的原因让用户照着修。

## 已知边界

- 端口归属是**推断**，不是确证。
- 提示块要**重启 DSH** 才看得见（宿主半端不随页面刷新加载，刷新页面不会生效）。

## 升级

```
dsh plugin --profile <profile> add dsh-cpa-switch
```

装完**重启 DSH** 生效。无配置变更、无破坏性改动。
