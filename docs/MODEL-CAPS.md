# 模型能力维护手册（上下文窗口 / 看图能力）

> 读者：发现「渠道里多了个模型」或「某个模型的窗口 / 图片能力不对」的人 / agent。
> 本文件只写**怎么查、怎么补、补之前要什么证据**。
> 为什么这张表至今还得人手维护 → [决策记录](../.agents/notes/2026-10-06-why-manual-table-remains.md)。
> 表本身的字段语义 → [src/model-caps.ts](../src/model-caps.ts) 的文件头（**唯一事实源**）。

## 一句话

**检测到新模型，先查两样：① 上下文窗口 ② 有没有看图能力。**
少查一样，用户得到的就是一个假数字或一个假能力 —— 而**两者都不报错**。

（思考档位是**另一条独立的事**，见文末「附」；它要发真实请求实测，
不属于「新模型体检」这一步的必做项。）

## 为什么这件事不能省

| 少做了什么                   | 用户看到什么                                                   | 有没有报错                                       |
| ---------------------------- | -------------------------------------------------------------- | ------------------------------------------------ |
| 没登记窗口                   | 上下文显示 **262K**（宿主兜底），压缩早早触发                  | **没有**                                         |
| 窗口填大了                   | 压缩晚点触发；真超了报一次 `context-overflow`                  | 有（可接受）                                     |
| **没标看图能力**             | 附加图片时**在发出前就被拒**，宿主点名说这个模型不支持图       | 有，但**结论是反的**：用户以为模型不行，其实没标 |
| 图像标错（明明不支持却标了） | 图片发出去、消息已落库、provider 中途拒绝 ⇒ **会话卡死**在重试 | 有，但**不可逆**                                 |
| 没查档位、模型其实关不掉思考 | 界面上有个「关」，选了照样思考                                 | **没有**                                         |
| 档位方向反了没对调           | 选「开」反而想得更**少**                                       | **没有**                                         |

`262144` 是宿主 `dsh-llm-pi-ai` 的 `DEFAULT_CONTEXT_WINDOW`，**不是任何模型的真实能力**。
看到 262K 就该怀疑「表里没有它」，而不是相信这个数。

⚠️ **看图能力的方向与窗口相反**：窗口写小了只是压缩早点触发；图像**漏标**会让功能
看起来不存在，**多标**会让会话卡死。所以它是「不确定就不标」，窗口是「不确定就填大」。

## 三道防线（从自动到人工）

1. **运行时自动补窗口**（`src/caps-overrides.ts`）—— 每次**读全**渠道目录后，
   把「表里没有、渠道侧有出处」的窗口补进 `storages/cpa-model-caps-overrides.json`，
   下一次推送就生效。**更新渠道插件 → 重启 CPA → 自动完成**，不用发版。
   - 只在**代码表没有该模型**时补（表是人写的有出处值，运行时数据不许覆盖它）。
   - 渠道侧**没有出处就什么都不写** —— 不编数字。
   - ⚠️ **看图能力不自动补**：标错的代价是会话卡死且不可逆，必须人过一眼再写。
2. **体检脚本**（`scripts/audit-model-caps.mjs`）—— 给人看的报告：哪几条能立刻补、
   哪几条漏标了看图能力、哪几条和出处对不上。
3. **人工补表**（`src/model-caps.ts` 的 `CALIBRATED`）—— 只有这一层能改
   **看图能力**与**思考档位**，也是「有出处」这件事的最终归档。

## 步骤

### 1. 发现新模型

```powershell
node scripts/audit-model-caps.mjs          # 退出码 0 = 没有可执行项
node scripts/audit-model-caps.mjs --json   # 机器读
```

它会读每个托管渠道的 `modelsPath`（见 [channels/registry.ts](../src/channels/registry.ts)），
与表逐个对照。**没有 CPA 在跑时它会以退出码 2 明确失败**，不会假装通过。

判读：

| 分类            | 含义                               | 怎么办                                    |
| --------------- | ---------------------------------- | ----------------------------------------- |
| `actionable`    | 表里没有、渠道侧**有**窗口出处     | 照抄建议行进表（**退出码 1**）            |
| `noSource`      | 表里没有、渠道侧也没出处           | 按口径走兜底，**不算待办**                |
| `mismatch`      | 两边都有但窗口数值不同             | 复核后改表（**退出码 1**）                |
| `imagesMissing` | 表里有、渠道说支持看图却没标       | 补 `supportsImages: true`（**退出码 1**） |
| `stale`         | 表里有、目录里没有                 | **别急着删**：供给面会波动                |
| `flagged`       | 表里有条目但只有档位标记、没有窗口 | 按渠道口径走兜底，属正常                  |

### 2. 找窗口与图像能力的出处（按可信度从高到低）

| 渠道      | 出处                                                                                                                                             | 可信度                       |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------- |
| WorkBuddy | `$DSH_HOME/.workbuddy-catalog.json`（桥写的实时目录快照，逐模型带 `contextWindow` / `supportsImages`）；离线档是桥的 `FALLBACK_WORKBUDDY_MODELS` | **官方**：随包发布的真实源码 |
| ZCode     | cpa-multi-plugins `PROTOCOL.md`「模型目录」                                                                                                      | **官方**                     |
| Qoder     | 第三方 Qoder CN Proxy 仓库的发布说明                                                                                                             | **第三方**，未官方确认       |
| Trae      | **没有**：`models/groups` 只给 `id`/`name`                                                                                                       | 无                           |

⚠️ **同一模型名在不同渠道上限与能力都可能不同**（`glm-5.3` 在 ZCode 侧是 1M/128K）。
**不许把 WorkBuddy 的值搬到 Trae** —— 表按渠道分开存就是为这件事。

### 3. 看图能力：两个方向都要留神

- **渠道说支持、表里没标** → 补 `supportsImages: true`（体检脚本会列出来）。
- **渠道说没有、但你有实测或官方文档说支持** → **以证据为准，不跟着渠道改**。
  本仓有先例：`glm-5.3` 官方文档曾写「仅文本」，而 CPA 直连差分实测证明它是真视觉
  （真图读出 2831、空白图答 NONE）—— 那种情况标上是对的，别被渠道的 `false` 推回去。
- ⚠️ **表里只出现 `true`，没有 `false`**：不写 == 不支持 == 没查，三者在宿主侧效果相同
  （都落 `DEFAULT_INPUT = ["text"]`）。所以「有反证的保持不标」，不是「标 false」。

### 4. 补表并验证

```powershell
# 改 src/model-caps.ts 的 CALIBRATED，注释里写清出处与日期
node node_modules/vitest/vitest.mjs run tests/model-caps.test.ts tests/model-caps-audit.test.ts
node scripts/audit-model-caps.mjs          # 退出码 0
pnpm build                                  # lib/ 才是被加载的产物
```

### 5. 收尾

- 窗口值补进代码表后，**运行时补丁表里的同名条目可以留着**（表优先，补丁自动失效）。
- 真机确认：重启 DSH → 选择器里该模型窗口正确 → 附件区能选图片（不是灰的）。

## 附：思考档位（另一条独立的事）

只有**实测反证**才写标记，且必须**至少三次重复**（单次会翻类 —— 2026-10-12 复测时
上一版名单一半翻了类）。

```powershell
node scripts/probe-cpa-stream.mjs --case think --model <渠道>/<模型> --repeat 3
```

⚠️ **会发真实请求、消耗额度**。

| 观测                            | 标什么                                  |
| ------------------------------- | --------------------------------------- |
| `off` ≈ 0、`high` 明显有        | **不标**（这是合格的开关，默认行为）    |
| 两档都**完全不**思考            | `reasoningEfforts: false`（摘掉档位）   |
| 两档都思考、`high` 反而**更少** | `reasoningEffortsSwapped: true`（对调） |
| 两档区间**重叠**（测不准）      | **一律不标**                            |

⚠️ **「关不掉」不是「测不准」**：`kimi-k3.1-pro` 的「关」照样思考 200/274/415 字，
那是**关不掉**（渠道也写着 `canDisableThinking: false`），按维护者口径摘掉档位。
